# Windows W4：可重复装配与内部预览ZIP

2026-10-24继续实施。W1—W3已保留在独立codex/windows-portable分支的阶段提交；本阶段增加维护者构建工具及退出/中断恢复，公开发行与W5完整验收仍未完成。[W3](./W3.md)及历史结果不改写。

## 维护者重新构建

```powershell
.\scripts\build_windows_release.ps1 -InternalPreview
```

先提交当前源代码。默认复用已校验W1运行时/两份模型；在新隔离目录按package-lock执行npm ci/build，复制backend/launcher源码、React静态资源和四个CMD，再校验清单、生成ZIP、校验CRC和SHA-256。用户解压后不需要Python/Node/npm或另行下载模型。

输出目标可用-OutputDirectory指定；省略时读取本机忽略的build/windows-release/output-preference.json，否则落到build/windows-release/exports。默认包名包含源提交号；已有输出/阶段目录不覆盖，重复构建可指定新的-Name。固定ZIP条目顺序、时间戳和压缩参数；相同输入在同构建工具版本下可重复，跨压缩库版本不承诺字节完全相同。包旁JSON记录ZIP摘要、源版本间接绑定的清单摘要与未完成门禁。

当前必须显式-InternalPreview。原始wheel来源尚未由installed RECORD副本重建；app-local VC支持资源仍来自已签名的本机安装，正规再分发来源/条款与最终NOTICE尚未核清；W5也未完成。没有此参数时构建明确拒绝，不把内部包标成公开发行版。随包保留Python依赖的原许可文件，补前端许可文本及licenses/THIRD_PARTY_INVENTORY.json；清单是盘点，不冒充许可审核完成。

## 数据与更新

从空目录按白名单装配，不复制开发.env、data、cache/temp/logs/state、reports、eval、Git、node_modules或故障探针。portable-manifest列出所有发布资产，运行生成的data不属于资产清单。ZIP根内使用说明解释四入口、API Key、目录布局、正常停止、备份/移动/删除及浏览器外写边界。

更新代码时复用已固定的模型/运行时后重新构建；改变依赖、模型或数据库版本需更新兼容合同并复验。首版不做任意数据迁移：停服并外部备份后，只有兼容的data可以迁移；跨Windows账号/电脑需重新填Key。浏览器localStorage/sessionStorage及缓存/历史位于浏览器用户目录，可能在AppData，不随ZIP删除；原生库、显卡驱动和系统的完整外写仍待W5，不宣称零外写。

## 退出和异常恢复

便携关闭流程分阶段记录Sparse停止、缓存释放和模型预热等待异常；某步异常仍继续其他清理。日志给出失败阶段，正常结束等待任务，超时强制结束仍由用户确认，不自动结束其他程序。

强制中断上传可能留下processing记录和部分向量。便携启动在开放检索前清理这些文档的部分向量/结构化单元，标为failed并提示重新上传；上传文件保留。失败清理拒绝启动且可下次重试，不把不完整内容当成功入库。已经ready的文档不在清理范围；源码模式保持原行为。

测试见[test_portable_w4.py](../../tests/test_portable_w4.py)及[probe_w4.py](./probe_w4.py)。后者仅用于新解压的build/windows-release测试目录，在真实Chroma写入后/真实Sparse代构建后用外部探针设置暂停点，再测试强制停止或正常等待；暂停代码不写入应用或ZIP。不是断电、硬盘损坏或所有崩溃位置的穷尽验收。实际结果统一记录[TEST-009](../../new_docs/测试/TEST-009-本地运行与回滚验证.md#w4-result)。
