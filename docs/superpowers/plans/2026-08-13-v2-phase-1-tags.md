# 阶段 1：多级树形标签与筛选检索实施计划

> 依赖：阶段 0 准备（分支 + 基线测试）。
> 设计依据：`docs/superpowers/specs/2026-08-13-rag-v2-optimization-design.md` 第 5 节。
> 原则：测试先行、每步小提交、不动生产数据、不改 OCR 与前端主架构。

## 1. 目标与边界

- 目标：文档可挂多个多级标签；检索可按标签（含子孙）筛选并取并集；不带标签的调用
  行为与现状完全一致。
- 边界：不实现 LLM 自动打标签；不做标签权限；Streamlit 只加最小过渡选择器，不重写
  Streamlit 前端；不改 Chroma chunk metadata。

## 2. 任务分解（按顺序执行）

### 2.1 Schema v2 与显式迁移

- 文件：`backend/services/metadata_schema.py`
- 内容：
  1. `SCHEMA_VERSION = 2`；
  2. 新增 `TAGS_SCHEMA`（tags）与 `DOCUMENT_TAGS_SCHEMA`（document_tags），并入
     `_SCHEMAS`；
  3. 迁移函数 `migrate_v1_to_v2(connection)`：检测 `schema_meta.schema_version == 1`
     且表完整 → 建两张新表 → 事务内将 `schema_meta` 写为 2；重复执行幂等；
  4. 空库 bootstrap 直接创建 v2 全量 schema；
  5. 未知版本/未版本化库继续抛 `UnsupportedSchemaError`。
- 失败测试先行：存量 v1 库迁移后业务行数不变；重复迁移幂等；版本 3 或不完整表拒绝。

### 2.2 标签服务

- 新文件：`backend/services/tag_store.py`
- 内容：
  1. `create_tag(tag_path)`、`rename_tag(old, new)`（事务内批量更新两张表）、
     `delete_tag(tag_path)`（级联）、`list_tag_tree()`（含每标签文档数）、
     `set_document_tags(document_id, paths)`、`get_document_tags(document_id)`、
     `expand_tag_paths(paths) -> list[path]`（前缀展开，父含子孙）；
  2. 路径规范化与校验：段非空、无首尾 `/`、`/` 分隔、深度 ≤ 6、总长 ≤ 200、
     段去除首尾空白；非法值 422；
  3. `resolve_document_ids(paths) -> list[document_id]`（供检索过滤使用，并集去重）。
- 失败测试先行：重命名后旧路径文档同步更新；删除标签后关联清空但文档保留；
  展开语义（选 `课程课件` 命中其全部子孙标签文档）；路径校验各非法用例。

### 2.3 上传与文档 API

- 文件：`backend/routers/upload.py`、`backend/models/schemas.py`
- 内容：
  1. `POST /api/upload` 表单增加可选 `tags`（JSON 数组字符串或重复字段，选定其一后
     全项目一致）；入库事务内写 `document_tags`；标签非法时 422 且清理失败产物；
  2. `GET /api/documents` 返回项增加 `tags`；
  3. `PUT /api/documents/{id}/tags` 整体替换标签集（不存在文档 404）；
  4. `GET /api/tags` 返回树 + 计数；
  5. `DELETE /api/tags/{path}`、`PATCH /api/tags/{path}`（重命名，body 含新路径）；
  6. 删除文档的级联清理补上 `document_tags`（依赖外键 ON DELETE CASCADE，验证即可）。
- 失败测试先行：上传带标签 → documents 与 chunks 均就绪、标签可查；非法标签 422；
  整体替换幂等；删除文档后关联行清空。

### 2.4 检索过滤

- 文件：`backend/services/vector_store.py`、`sparse_retriever.py`、`retriever.py`、
  `retrieval_trace.py`、`backend/routers/chat.py`、`backend/models/schemas.py`
- 内容：
  1. `ChatRequest` 增加 `tags: list[str] = []`（缺省全库）；
  2. chat 路由把 tags 传入检索（对话持久化不受影响，tags 不落库、不进入历史）；
  3. Dense：`search_by_embedding(..., allowed_document_ids=None)` →
     `where={"document_id": {"$in": [...]}}`；集合为空且要求过滤时直接短路返回空；
  4. BM25：`search(query, top_k, allowed_document_ids=None)`，`_get_index` 缓存键加入
     `tuple(sorted(allowed_document_ids))`（空集合 = 不过滤，沿用旧键），建索引前过滤
     chunk 快照；
  5. Hybrid：两路同传过滤后再 RRF；
  6. 空结果文案：「当前筛选范围内未找到相关文档内容。请尝试调整标签筛选或查看全部
     文档。」；全库空结果保持现有文案；
  7. Trace 记录本次过滤的标签与命中文档数（`RetrievalTrace` 增加可选字段，向后兼容）。
- 失败测试先行：Dense/BM25/Hybrid 各自只命中目标文档；多标签并集；子孙标签命中；
  空标签列表 = 全库；过滤后空结果文案；Trace 含过滤信息且旧结构仍可解析。

### 2.5 Streamlit 最小过渡件

- 文件：`frontend/app.py`（最小改动）
- 内容：上传区读取 `/api/tags` 渲染多选树（`st.multiselect` 按路径字符串）；侧栏标签
  筛选器，选择后随问题提交 `tags`；顶部显示当前筛选徽标。
- 验收：过渡件可用即止，不做样式打磨（随 Streamlit 移除）。

### 2.6 测试与验收

- 新增测试文件：`tests/test_tag_store.py`、`tests/test_schema_migration_v2.py`、
  `tests/test_tag_retrieval.py`；更新 `tests/test_api.py`、`tests/test_retriever.py`、
  `tests/test_sparse_retriever.py` 的相关断言；
- 集成：隔离 SQLite + Chroma 下走完整「上传带标签 → 三模式检索 → 引用」链路；
- 回归：全量 pytest 保持绿色；不带标签的既有测试全部不改。

## 4. 阶段验收标准

1. schema v2 迁移在「存量 v1 库」与「空库」两条路径下均通过，业务数据无丢失；
2. 标签 CRUD、重命名、删除级联、文档挂标签全部可用；
3. 三模式检索按标签过滤正确，并集与子孙语义正确，Trace 可见过滤信息；
4. 不带标签的调用与阶段 0 基线行为一致（回归测试不改）；
5. 隔离环境端到端冒烟通过；生产 `data/` 全程未动；
6. 全量 pytest 绿色，提交主题清晰可回溯。

## 5. 验收反馈修正（2026-08-13，用户手动验收确认的需求）

用户手动验收反馈确认了以下交互问题与形态，作为本阶段的补充任务：

### 5.1 已上传文档修改标签

- 文档列表每个文档提供「编辑标签」入口：现有标签多选 + 新标签输入 + 保存按钮，
  调用 `PUT /api/documents/id/{document_id}/tags`（后端已实现，零后端改动）；
- 验收：改标签后列表 🏷 展示即时更新，标签树计数同步变化。

### 5.2 独立新建空标签

- 侧栏新增「标签管理」区：路径输入 + 「➕ 新建标签」按钮 → `POST /api/tags`；
  展示现有标签与文档数（只读列表）；
- 上传区同样提供新建标签按钮，**创建成功后自动选入本次上传的标签多选框**；
- 验收：可不依赖上传、单独创建空标签；新建后立即可在筛选器与上传选择器中看到。

### 5.3 上传三段式暂存 + 确认

- 选择文件后**只暂存**（记录到 session_state，不自动提交）；
- 展示暂存文件列表 + 标签选择 + 「✅ 确认上传」按钮；点击确认后才逐个提交
  （后端就绪检查、失败保留暂存区可重试）；
- 全部成功后清空暂存区并轮换上传控件；取消/移除暂存文件不产生任何后端请求；
- 验收：选完文件不会自动入库；确认后才入库；失败文件可原地重试。

### 5.4 测试与回归

- `tests/test_frontend_app.py` 同步更新：暂存流程、确认上传、新建标签自动选中、
  改标签入口的页面状态回归；
- 全量 pytest 保持绿色；提交主题：「fix: rework Streamlit upload staging and
  tag editing UX」。

## 6. 风险与备注

- Chroma `$in` 过滤的 id 数量上限需在集成测试中用真实规模验证（本地知识库量级预期
  远低于任何限制）；
- BM25 缓存键加入标签集会使不同筛选组合各自建索引；本地内存代价可接受，后续若标签
  组合爆炸再评估按文档集合预过滤的替代方案；
- 阶段 2 的 OCR 与阶段 3 的 SPA 都不在本阶段范围内，避免混入提交；
- 文档库预览端点与列表 `tags` 查询参数属阶段 3（见设计文档 6.2），过渡件不提前实现。
