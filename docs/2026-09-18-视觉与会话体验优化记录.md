## 1. 本轮完成内容

### 1.1 视觉模型设置

- React 设置页新增视觉模型区域，可选择“跟随问答模型”或“自定义”。默认跟随问答模型，避免重复维护同一连接；自定义模式可使用不同 provider、Base URL、模型和 DPAPI 密钥。
- 文字识别和图片描述分别控制思考模式、思考强度、Temperature、最大输出长度与超时；最大图片边长、单文档最大调用数和三个识别场景仍独立配置。
- 新增真实图片连接测试。它使用页面未保存草稿和程序生成的图片，不修改持久化设置；正式识别仍只在下一次上传或重新解析时生效。

### 1.2 OCR/视觉链路诊断

- 单个后端进程内的视觉请求按 1 路执行，正常调用沿用 SDK 的有限重试；草稿连接测试不自动重试，避免测试按钮造成重复消耗。
- 上传警告区分限流、超时、空输出、输出截断和一般服务错误，并尽量保留服务商错误码、状态码和 request ID，便于与服务商控制台对照。
- 新增 `scripts/validate_vision_settings.py`，可用程序生成的图片和两页扫描式 PDF 验证“设置解析—多模态请求—OCR 入库前输出”链路。该脚本会真实调用已保存模型，执行前应确认费用和额度。
- 结论边界：本地串行能降低本进程并发，但免费模型是否存在账号级 QPS、并发或每日额度仍只能结合 429、request ID 和服务商控制台确认，不能仅凭“没有可提取内容”反推为限流。

### 1.3 文档预览布局

- 原先采用图片浮动/文字环绕，文字何时越过图片由图片实际渲染高度、段落高度和浏览器排版共同决定，因此不同页面看起来不一致。
- 现在把同一原图和它关联的 OCR 文本组成显式布局组：组内左图右文，组结束后后续正文恢复整行。图片加载不会再改变不相关正文的环绕边界。

### 1.4 来源引用自动定位

- 引用抽屉不再只在首次挂载时滚动；它会等待抽屉打开动画完成，定位实际高亮标记的首个可见矩形，并在图片加载造成布局变化后重新校正。
- 用户主动滚动后停止自动纠正，避免界面与用户争夺滚动位置。
- 自动化覆盖高亮目标选择和滚动；人工使用“实验2.pdf 第 13 页”反复打开/关闭 5 次均能看到命中区域。用户随后手动复测未发现问题。

### 1.5 React 启动入口

- `scripts/start.ps1` 默认构建并启动 React SPA，由 FastAPI 在 `http://localhost:8000` 托管；旧 Streamlit 仅在显式兼容参数下启动。
- 启动打开的 URL 带本次缓存戳，使浏览器重新请求入口文件；这能避免旧 `index.html` 命中缓存，但不会清除浏览器中的用户数据。

### 1.6 模型思考内容

- 后端从兼容接口中单独接收 `reasoning_content`，通过 NDJSON `reasoning_delta` 发送，不混入正文、引用提取或下一轮历史上下文。
- 当前轮有思考时默认展开；第一段正式正文到达后自动折叠，用户仍可点击展开。成功消息将思考保存到 schema v5，历史会话重新打开时默认折叠。
- 上游只返回思考、没有正文时按空回答失败处理，不再出现界面长期转圈或把空正文记为成功。失败/中止请求的临时思考不保存为成功历史。

### 3.2 功能可用，但质量或兼容性仍需完善

1. **OCR 专项评测**：目前有调用测试、错误诊断和人工预览，但没有带人工真值的字符准确率、表格、公式和复杂版面评测；OCR 表格主要作为段落保存，不等同于结构化表格恢复。
2. **视觉服务商额度**：本地并发已限制为 1，但账号级免费额度、QPS 和每日配额由服务商控制；应以 429、服务商错误码/request ID 和控制台记录核验。
3. **思考字段兼容**：当前支持常见 `reasoning_content` 协议；其他 OpenAI-compatible 端点可能使用不同字段、忽略开关或不流式返回思考，需要逐服务商验证。
4. **引用定位极端情况**：当前覆盖抽屉动画和图片迟加载；超长文档、缩放变化及包含多个同文片段时仍值得增加端到端压力用例。
5. **CPU Reranker 延迟**：功能正确，但本地 CPU 精排仍是主要延迟来源之一。
6. **前端包体积**：生产构建通过，但主 JavaScript chunk 约 1.31 MB（gzip 约 416 KB），应按路由或重型面板拆包。
7. **依赖弃用**：FastAPI `on_event`、PyPDF2、Starlette TestClient/httpx、`pkg_resources` 等仍有弃用警告。
