## 三、评估中发现的真实系统缺陷（优化时的量化点）

1. **引用格式端到端断裂**（P3-5 量化点）：`llm.py` 的 SYSTEM_PROMPT 要求引用 `【文档名，第X页】`，
   但 `retriever.format_retrieval_context()` 给上下文打的标签是 `【来源N - 《文档名》第X页】`，
   LLM 照抄后者 → `citation.py` 的正则解析不出 → 前端引用几乎全靠 citation.py:67 的
   fallback（取检索 top3）伪造。修好后 citation_emission_rate 应从 11.8% 大幅上升。
2. **docx 表格完全丢失**（P3-4 量化点）：parser 忽略表格。数据集 q11/q12 的证据在
   《2024技术发展报告》的表格里，baseline 必不命中，是表格提取的金丝雀——做完 P3-4 这两题应转为命中。
3. **相似度阈值形同虚设**：retriever.py 硬编码 `distance <= 1.5`（余弦距离域 [0,2]），实测所有
   检索 distance 在 0.3~0.5，从不触发过滤。拒答全靠 LLM 自觉（目前它确实自觉，refusal 100%）。
4. **chunk_index 按页重置**：chunk ID 唯一性依赖 `文档名_p页_c序号` 三元组，改切分逻辑时别破坏。

## 四、阶段一施工注意点

**P0-1 换中文 Embedding（bge）：**
- `embedding.py` 是 `SentenceTransformer(model, local_files_only=True)` —— **必须先联网下载模型**
  （临时去掉该参数跑一次或 `huggingface-cli download`），否则直接报错。设备内存紧就用
  `BAAI/bge-small-zh-v1.5`。bge 检索 query 侧建议加指令前缀（"为这个句子生成表示以用于检索相关文章："），
  是否加对分数影响可用 eval 直接 A/B。
- 换模型后生产库 `data/chroma_db` 维度不兼容需删除重传；**eval 不受影响**（每次 run 都重建隔离索引）。
- 验证：`run --label p0-1-bge` → `compare baseline p0-1-bge`，预期 hit_rate/MRR 显著上升、
  false_refusal_rate 显著下降。

**P0-3 递归切分 + 文本清洗：**
- 按方案自实现递归切分（\n\n → 句 → 子句 → 字符兜底），CHUNK_SIZE 500→800、OVERLAP 50→150。
- 保持 `chunk_document(pages, chunk_size, overlap) -> List[DocumentChunk]` 签名不变，eval 零改动。
- 数据集的检索命中判定用 snippet 文本包含（≤30字/单句内），对切分改动鲁棒，页码变化无影响。
- 验证：compare 里重点看 chunk 总数变化（baseline 是 50）和回归题清单。

**P0-2 Milvus 迁移**：配套清单见 `eval/README.md` 设计要点第 4 条（隔离路径走环境变量、
retrieve() 返回契约、相似度 vs 距离语义相反）。迁移验收 = compare 检索指标持平。

**通用工作流**：每完成一项 → `run --label <步骤名>` → `compare baseline <步骤名>` →
回归题清单必须为空才算过 → commit 时可顺带提交该 run 的 report.json/md（`git add -f`，runs/ 默认忽略）。
