# BM25 持久化 P4 同期对照结果

P4已在现有固定1000篇文档、2914个chunk和120道题上完成。同期旧后端`rank_bm25_memory`与新后端`bm25s_mmap`各运行3个独立进程；每个进程先执行1次冷查询，再按完全相同顺序执行120次暖态Hybrid检索。Embedding与Reranker均为`cuda:0`，Reranker使用FP16，生成LLM和出站网络关闭；每轮Chroma/SQLite使用独立副本，运行后副本已清理。

正式结论以[修正版汇总](./runs/p4-20260903-r1/summary-v2.json)和[修正版报告](./runs/p4-20260903-r1/report-v2.md)为准。6份逐轮`result.json`、`retrieval.jsonl`和`sparse_top50.jsonl`均保留在对应后端/run目录。

## 正确性和质量

- 六轮BM25 Top1/5/15/50相对同期旧后端run-01均为120/120有序一致；最大分数差`2.8421709430404007e-13`，低于`1e-12`容差。
- 六轮质量完全相同：文档Hit `0.99`、Recall `0.965`、MRR `0.9583`、all-gold `0.94`、多文档all-gold `0.9048`、Evidence覆盖`0.964`、精确证据包含`0.96`。
- 20道不可回答题仍全部进入非空上下文，`unanswerable_llm_entry_rate=1.0`；P4没有解决既有拒答门控缺陷。
- 独立GPU进程间Dense顺序存在已知ANN波动：相对control run-01，control run-02/03只有102/120和105/120完全一致，最终Top5各119/120；mmap三轮处于同类范围。该波动不能归因于Sparse后端。P3使用同一Dense候选的因果回放中，Sparse、RRF、Reranker输入和最终Top5仍均为120/120一致。

初始[失败汇总](./runs/p4-20260903-r1/summary.json)错误地把所有独立GPU进程的Dense/RRF/Reranker/final逐题顺序完全相同设为Sparse门禁，因此如实判失败并保留。修正版只调整汇总口径，不修改任何原始run文件：BM25有序结果、质量指标和P3同Dense回放作为Sparse因果门禁，独立进程的Dense波动作为观测数据保留。

## 稳定性和完整性

- mmap三轮健康路径均未调用`get_all_chunks()`，未构建`BM25Okapi`，每进程只加载索引1次。
- mmap三轮各执行24题、4线程并发只读，共72/72与顺序结果一致。
- 六轮源数据集、代码hash一致；封存Chroma/SQLite和Sparse索引运行前后指纹不变；隔离工作副本已删除。
- mmap三轮关闭后索引映射数均为0；旧后端三轮均可正常运行，证明当前回滚路径可用。
- GPU设备均验证为NVIDIA GeForce RTX 4060 Laptop GPU；两后端GPU峰值完全一致，BM25优化没有新增GPU占用。
- P4完成后全量Python回归为759项通过、3项跳过、7个既有弃用警告。

## 结论边界

P4证明：在当前固定1000篇/120题上，持久化mmap后端保持BM25排序和聚合质量，显著降低Sparse阶段耗时，并带来约3.3%的完整暖态平均耗时改善；代价是单代约4.06 MiB索引和本轮约8.10 MiB额外进程磁盘读取，GPU开销不变。

这仍不是采用或生产切换结论。端到端平均改善幅度小于Sparse阶段改善，且存在跨进程Dense/GPU波动；P5需判断该收益是否值得承担静态generation和动态数据生命周期复杂度。结果不得外推到1万篇、8万篇或生产容量，也不能据此得出需要更换Milvus的结论。
