## 1. 背景与优化对象

CPU逐请求精排成本高。关系：优化[DEV-004 检索与模型推理](../开发/DEV-004-检索与模型推理.md)并通过[DEV-012 服务托管与启动停止](../开发/DEV-012-服务托管与启动停止.md)提供显式CPU/GPU启动profile。来源：[V3-3/V3-4记录](../../docs/新增测试集和运行优化v3方案.md)，测试[TEST-002 检索质量与性能](../测试/TEST-002-检索质量与性能.md)。

## 2. 实际改动与环境

保留.venv CPU回退，新增独立.venv-gpu；GPU使用cuda:0，Reranker FP16。设备/批量参数进入配置与测试；start默认GPU，cpu选项显式回退。

历史运行环境为Windows、Python 3.14、RTX 4060 Laptop GPU，报告记录torch 2.13.0+cpu与2.13.0+cu130。这里是本地历史证据，未重新安装、检测GPU或验证外部包可用性。

## 3. 优化前后数据

来源：[2026-08-23原报告](../../eval/crud_rag_1000/v3/runs/cpu-gpu-baseline-comparison-20260823/cpu-gpu-comparison.md)。同一1000文档、2914 chunks、120题draft；Hybrid、Dense/BM25 K15、RRF60、精排K15、Top5、threshold0.67、recursive400/80。CPU FP32与GPU FP16同时变化，不是纯硬件单变量实验。

| 指标 | CPU | GPU | 解释 |
|---|---:|---:|---|
| 入库耗时 | 1658.28s | 289.48s | 全新隔离索引 |
| 检索mean | 10.022s | 0.315s | 包含首题冷启动 |
| 检索P95 | 11.202s | 0.312s | 仅检索、不含LLM |
| 去首题mean | 9.959s | 0.242s | 热态对照 |
| document_hit_rate | 0.99 | 0.99 | 汇总一致 |
| document_recall | 0.965 | 0.965 | 汇总一致 |
| all_gold_docs_recalled_rate | 0.94 | 0.94 | 汇总一致 |

Top1 chunk 120/120一致，Top5集合/顺序118/120一致；中间Dense阶段有差异。GPU峰值allocated/reserved为2397.9/2764.0 MiB。

## 4. 风险、副作用与结论

历史结果超过方案30%耗时下降门槛，但不是LLM端到端加速，也不是v3.1结果。FP16可能改变近似分数和排序；GPU环境失败时需明确回退，不能静默宣称仍在GPU。

20道不可回答仍全部进入最终上下文，性能改进没有解决[BUG-003 不可回答题仍入选上下文](../测试/BUG-003-不可回答题仍入选上下文.md)。本次文档更新未重跑；2026-08-28已有新增单次GPU证据如下，温度与多请求吞吐仍未验证。

## 5. 2026-08-28新版GPU基线补充

[TEST-002新版记录](../测试/TEST-002-检索质量与性能.md#baseline-v31)已经确认v3.1的120题一次跑完，两模型实际cuda:0；入库274.67s，暖态0.2849s，P95 0.324s，allocated/reserved峰值2397.9/2764.0MiB。
本次暖态0.2849s比旧GPU记录0.2420s慢约17.72%，差异主要在重排；不是又一次CPU/GPU对照，也不支持把变化全部归于GPU或题库修改。
本次无需重新迁移GPU，后续关注同索引、同参数预算的重复计时及模型缓存/候选数代价；生成模型调用仍禁用。设备事实与当前质量瓶颈分开处理。
