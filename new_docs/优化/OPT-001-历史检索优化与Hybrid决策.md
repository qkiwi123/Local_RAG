## 2. 历史改动与取舍

| 阶段 | 问题与改动 | 当前使用方式/限制 |
|---|---|---|
| P0 | 稳定来源编号、移除无标记兜底引用 | 保留协议；旧报告留作起点 |
| P1-1 | 改用BGE large中文向量 | 维度变化需重建，不复用384维旧索引 |
| P1-2 | DOCX表格按原序进入文本 | 保留表格金丝雀回归 |
| P1-3 | token-aware递归切分 | 质量与chunk数同时评估 |
| P1-4 | Dense距离阈值校准为0.67 | 是历史数据选择，不能当所有语料最优 |
| P1-5 | 加Cross-encoder精排 | 提高小样本质量，增加CPU延迟 |

## 3. P1-5前后结果

来源：[p1-4→p1-5原对照](../../eval/results/p1-5-reranker/compare-p1-4.md)。这是旧小样本、68 chunks的历史，不是structured-v2/120题结果。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| hit_rate | 94.12% | 100.00% |
| recall | 88.24% | 94.12% |
| MRR | 81.37% | 97.06% |
| strict_accuracy | 94.12% | 100.00% |
| 报告总延迟 | 2.043s | 9.314s |

原报告无回归题，改善q05；代价是报告总延迟增加7.271s。不能用这组质量收益证明CPU性能可接受。

<a id="hybrid"></a>
## 4. P2-1消融与未切换决策

[decision.md](../../eval/results/p2-1-hybrid-retrieval/decision.md)记录：27题中Hybrid+Reranker与Dense+Reranker的Hit/Recall/MRR无增益，q18不可回答题从Dense空结果变成词法候选进入上下文；因此当时不切生产默认、不继续付费LLM全量对照。

代码保留三模式供后续语料实验；这不是删除Hybrid，也不是永久否定它。当前代码部署默认仍dense，但实际请求可被设置覆盖，应查Trace。

## 5. 最终结论与后续

历史实验已完成，本次未重复执行。不要把不同数据集、切分或评分版本串成一条无条件上升曲线。性能后续见[OPT-002 CPU到GPU检索迁移](../优化/OPT-002-CPU到GPU检索迁移.md)；新版校准见[OPT-003 候选深度与拒答门控](../优化/OPT-003-候选深度与拒答门控.md)。
