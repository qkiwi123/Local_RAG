## 1. 需求背景

用户需要依据知识库回答问题，并理解“哪些资料被召回、为何被筛掉、哪些最终进入模型”。不能只凭流畅答案判断质量，也不能把有检索结果等同于可回答。

来源：[数据链路详解](../../docs/数据链路检索过程与阶段选择策略详解.md)、[混合检索设计](../../docs/superpowers/specs/2026-07-18-p2-1-hybrid-retrieval-design.md)。

## 2. 功能需求与输入输出

| 编号 | 需求 | 结果 |
|---|---|---|
| R1 | 输入问题和可选标签范围 | 在指定文档集合中检索，不越范围 |
| R2 | 支持语义、词法与融合候选 | 可比较各阶段的排名和淘汰原因 |
| R3 | 生成答案附实际来源编号 | 编号只映射本次检索上下文 |
| R4 | 无有效上下文时停止生成 | 返回缺少相关资料提示，不伪造引用 |
| R5 | 可关闭问答模型 | 仅检索模式不调用改写或回答模型 |
| R6 | 区分候选数、最终数量和拒答判断 | 不能用一个“阈值”混同不同阶段 |
| R7 | 固定完整语料的词法索引可离线构建并复用 | 查询健康路径不全库扫描；索引与语料、分词和参数错配时显式失败 |
| R8 | 多轮追问的实际检索输入可解释、可评估 | 保留原问题与实际`standalone_question`语义；任何跳过改写的策略都不能静默改变默认，且必须有独立的召回、质量和时延对照 |

## 3. 质量要求与边界

质量同时考察文档命中、证据覆盖、多文档完整召回、拒答和引用；性能区分冷启动、检索、重排、模型生成，不设未经基线支持的绝对SLA。

当前支持Dense、BM25、Hybrid和可选Reranker，但尚无经过校准的最终拒答门控。Dense距离阈值只能约束Dense分支；Hybrid中的词法候选仍可能进入最终上下文。该缺口由[BUG-003 不可回答题仍入选上下文](../测试/BUG-003-不可回答题仍入选上下文.md)跟踪，不能写成已经解决。

P3已为固定全库增加显式`bm25s_mmap`业务路径：健康请求不再读取/分词全库或构建`BM25Okapi`，而是查询活动generation并按chunk ID批量回取Chroma正文。默认仍为`rank_bm25_memory`，生产未切换；空过滤立即返回，非空文档过滤保持当前“过滤后子语料建模”的精确语义。当前本地Chroma 1.5.9原生Sparse仍不可用，不能把该BM25S文件方案误写成Chroma本地Sparse；实现和证据边界见[OPT-005 P3](../优化/OPT-005-BM25持久化稀疏索引.md#phase-p3-result)。

P4在固定1000篇/120题上完成同期旧/新各3个独立进程对照：六轮BM25 K1/5/15/50和质量指标一致，Sparse暖态均值/P95下降72.80%/85.61%，完整暖态均值下降3.34%，GPU峰值不变。该结果满足进入P5的测量门禁，但不代表已决定采用、切换默认后端或具备动态生产生命周期；详见[OPT-005 P4](../优化/OPT-005-BM25持久化稀疏索引.md#phase-p4-result)。

P5拟条件采用`bm25s_mmap`：只替换Hybrid/BM25内部的Sparse实现，不改变当前`RETRIEVAL_MODE=hybrid`、Dense、RRF、Reranker、TopK、中文分词或BM25参数。正式生效前必须完成[OPT-005 P6协议](../优化/OPT-005-BM25持久化稀疏索引.md#phase-p6-plan)：生产专用generation、增删前持久标脏、重启后仍fail-closed、后台合并重建、标签过滤、成套恢复、原子切换与旧backend回滚。评测generation不得直接发布到生产。

不包含Milvus替换、联网搜索、知识库之外的事实保证。运行参数的实际取值以请求Trace为准，不能从历史默认值推测。

多轮追问当前在有历史且LLM开启时尝试调用一次`rewrite_followup`，其输出用于检索，最终生成仍保留原问题和有界历史；LLM关闭时不得调用改写。当前没有已验证的启发式跳过规则，也没有改写模式开关。评测数据集中的gold `standalone_question`只能作为标注/检索输入基准，不能替代真实改写耗时或回答质量结论；后续门禁见[OPT-006](../优化/OPT-006-Trace计量拆分与首字延迟优化.md#rewrite)。

## 4. 验收条件

- 标签范围、候选阶段和最终配额有可重复测试；Trace开关不改变排序。
- 来源协议不为无引用答案兜底附加来源。
- 外部生成质量与本地检索质量分开评估；draft数据只能产出预检结论。
- 拒答门控需要独立校准、误拒答分析和回归；当前整体验收仍保留此门禁。
- 持久化BM25替换前，固定1000篇语料120题在K=1/5/15/50的词法有序结果和同Dense候选下的Hybrid最终结果必须一致。
- 持久化健康路径不得逐请求或首次查询读取全库、重新分词或构建`BM25Okapi`；缺失、损坏、dirty及合同错配必须可诊断，评测不得静默降级。
- `allowed_document_ids`的None、空集合、非空集合语义均需回归；不得以“全库TopK后过滤”替代当前非空过滤的子语料BM25语义。
- 生产切换前，任何Chroma增删都必须先持久标脏；标脏失败拒绝写入，重启不得把dirty误判为ready；后台重建只能发布与最新源revision/摘要一致的generation。
- 只允许显式切Dense或显式回滚旧backend，不得在Hybrid全库请求中静默使用旧generation、查询时全量重建或隐式退回内存BM25。

关系：算法见[DES-003选择契约](../设计/DES-003-检索融合与上下文选择.md#contract)，现状见[TEST-002 检索质量与性能](../测试/TEST-002-检索质量与性能.md)，未完成优化见[OPT-003 候选深度与拒答门控](../优化/OPT-003-候选深度与拒答门控.md)。

2026-09-08：P6-A已完成上述动态生命周期的单进程隔离验收，包括新进程识别dirty及受控入口；生产影子构建、成套恢复与默认启用仍未验收。实际缺口及交付见[OPT-005 P6-A](../优化/OPT-005-BM25持久化稀疏索引.md#phase-p6a-result)。

## P6-C本轮边界（2026-09-08）

生产31篇/2620块的同期GPU回归中，新旧BM25 Top50为120/120一致，副本Sparse P95从89.389ms降至7.732ms。旧版复测自身也出现Dense/最终排序变化，且历史文档已确认Chroma/HNSW新进程重放造成ANN状态波动；用户确认该非BM25因果项不阻断本次切换。生产active现为`ready`并指向`production-shadow-20260908-r1`，两次生产配置新进程Sparse P95为72.411/72.965ms，均低于旧版110%上限。P5条件采用现已生效；Dense、RRF、Reranker和Hybrid参数不变，旧后端仍可显式回滚。

证据：[P6-C生产启用报告](../../eval/crud_rag_1000/v3_1/bm25_persistence_p6c/README.md)及[最终结果](../../eval/crud_rag_1000/v3_1/bm25_persistence_p6c/result-20260908-r2.json)；历史Dense边界见[DES-007](../设计/DES-007-评测隔离与数据契约.md#dense-variance)。未执行外部LLM、浏览器、虚构生产写入或长期流量观察。
