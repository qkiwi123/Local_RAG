## 1. 需求背景与使用环境

这是面向可信本地工作区的RAG系统，需要在Windows上可靠启动、停止、升级和排查，同时保留CPU回退环境，避免试验覆盖主数据。

来源：[现有启动与安全说明](../../README.md)、[启动脚本](../../scripts/start.ps1)、[停止脚本](../../scripts/stop.ps1)。

<a id="requirements"></a>
## 2. 运行与安全要求

- 明确主React入口、API入口与旧Streamlit入口。
- 启动前确认模型缓存、解释器、配置和端口；GPU不可用时显式选CPU，不掩盖设备切换。
- 停止只操作本次记录且身份匹配的进程；失败时保留定位信息。
- 数据库、原始文件、索引、OCR资产和设置应能一致性备份与恢复。
- 索引重建到独立目标，明确切换和回退流程。
- 验收使用隔离数据；模型调用需说明外部传输与费用。
- 不输出、提交或把密钥复制进文档。

## 3. 输入输出与边界

输入包括环境变量、构建产物、模型缓存及已有数据；输出为可访问服务、日志、PID记录及恢复证据。健康接口成功只证明服务可响应，不等于UI挂载、检索模型或外部服务就绪。

仓库没有已交付的Docker部署方案、统一认证、生产监控栈或备份恢复自动化。不能因为依赖列表含认证库就声称已有账号体系。不把开发CORS配置当生产安全配置。

<a id="acceptance"></a>
## 4. 验收条件

正常与reload模式都验证启停和端口释放；JS MIME正确且UI实际挂载；CPU/GPU身份可核对；恢复到隔离目录后文档、引用、会话和设置一致。恢复演练与公网部署安全本次未执行，仍须独立验收。

关系：架构[DES-001 系统架构与存储边界](../设计/DES-001-系统架构与存储边界.md)，运行用例[TEST-009](../测试/TEST-009-本地运行与回滚验证.md#cases)，操作手册[OPS-001 环境配置与服务启停](../运维/OPS-001-环境配置与服务启停.md)、[OPS-002 数据备份恢复与索引重建](../运维/OPS-002-数据备份恢复与索引重建.md)。

## 5. Windows单人本地交付要求（2026-10-03修订，分阶段实施）

用户确认Windows单人本地、目录自包含便携ZIP，接受首次填写API Key，并要求小改动快速交付。GPU优先、CPU备用均保留Hybrid、持久化BM25和Reranker；目标为解压具备运行条件、双击启动、一个目录管理及停服后整体移动/备份/删除。自动升级/恢复、组件管理和个人数据一键重置后置。W1/W2历史证据保留；2026-10-24继续完成W3四入口、实例归属、有限回退、同源和基础维护，本机结果见[OPS-005 W3](../运维/OPS-005-Windows单人本地发布与初始化方案.md#w3-result)。用户指定后续ZIP导出目录，只记录本机构建偏好且不覆盖既有输出；本轮未导出。无驱动Windows因缺电脑仍待验收，W4—W5和完整发布包未交付，本文测试中不表示已可直接给新用户使用。

- WR01：Windows x64便携ZIP自带可移动专用运行环境、CUDA依赖、预构建React及BGE large/重排两份模型；Windows 11为首个验收基线，无需用户预装开发工具、提权或首次联网安装依赖。优先验证单运行时支持GPU/CPU，不能以本机CPU张量检查替代无GPU/无驱动完整模型运行。
- WR02：首次校验随包资源并初始化空data，断网可完成本地启动；首代Sparse就绪后完整Hybrid检索。日常不编译、不安装/更新依赖、不下载模型；首版无可选组件下载器，损坏包不靠全局缓存补齐。
- WR03：默认GPU优先，实际编码/重排和设备校验失败时说明原因并确认CPU；CPU关闭重排FP16但仍启用同模型、Hybrid+bm25s_mmap、候选15/top_k=5。不因回退关闭重排/换Dense；仅新便携工作空间首次非空语料允许后台首代构建，保持源复核/校验/原子发布及旧生产受控门禁。oracle不依赖私人eval材料；依赖/模型一致不承诺不同设备耗时、排序或回答逐字相同。
- WR04：无Key可进设置与知识库、可做本地检索；生成/OCR默认关闭，用户填Key并开启后才调用。引用预览在本机发布档开启；外传范围、费用与本地/离线的区别清晰提示。
- WR05：沿用backend/与web/dist/同根布局，runtime/models/data/logs/cache/temp/state均在解压根内，不默认写AppData；维护入口可打开目录/日志。升级先按说明人工复制成套data，不覆盖源数据，不导入开发机.env、密钥或私有文件。
- WR06：同工作空间单服务进程；重复启动打开已有实例，其他端口占用不误判/误杀；停止及失败回收须验证进程身份。
- WR07：只监听本机，收紧发布模式Host、Origin及跨域行为，不对本机恶意进程、多Windows用户隔离或远程访问作安全承诺。
- WR08：首版停服后人工复制完整目录或整套data，恢复到新目录；业务导入前检查兼容，不支持的版本拒绝打开，自动迁移/升级/恢复工具后置。跨机密钥可重配，不把复制旧程序当数据库回滚，不自动迁移/删除当前开发库。
- WR09：干净Windows验证GPU优先及无GPU/无驱动CPU完整流程、首次离线、真实UI、人工备份/兼容升级、移动与清理；固定数据/模型/参数对照质量并分段计时，资源/包体/耗时实测，不用Linux单测替代。
- WR10：应用不主动修改注册表、全局PATH/环境变量、服务/计划任务、自启、防火墙或安全设置；模型/临时缓存显式重定向至项目内，跟踪子进程实际写入。操作系统/浏览器独立记录单列，不承诺绝对零痕迹，不擅自清理它们。
- WR11：停服后同电脑移动/换盘符/整目录复制，不依赖旧绝对路径、旧PID、全局模型或系统Python；跨机/跨用户Key可重新配置，不明文降级、不因Key失效阻断设置页。
- WR12：首版只有分类缓存清理与移除前准备；个人数据一键重置、组件移除工具后置。完整移除提示停服/外部备份后由用户删除整个目录，明确会连data一起删除。清理不越界、不误删上传原件/外部备份/模型或OCR资产、不误杀其他进程，失败明确报告。

详细交付与阶段顺序见[OPS-005](../运维/OPS-005-Windows单人本地发布与初始化方案.md#implementation-plan)，架构见[DES-001发布边界](../设计/DES-001-系统架构与存储边界.md#windows-release)，执行与验收见[DEV-012](../开发/DEV-012-服务托管与启动停止.md#windows-release)、[TEST-009](../测试/TEST-009-本地运行与回滚验证.md#windows-release)。
