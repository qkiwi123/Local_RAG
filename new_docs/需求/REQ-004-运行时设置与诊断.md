## 1. 需求背景

用户希望通过设置页调整问答模型和检索策略，并能知道历史回答使用了哪次设置。直接让浏览器改写部署文件会混淆密钥、重启配置和请求级参数。

来源：[设置方案及S1—S6记录](../../docs/前端设置功能优化方案.md)。

<a id="requirements"></a>
## 2. 功能需求

- 查看有效配置、字段来源和运行状态，不泄露密钥、不因查看页面冷加载模型。
- 保存允许动态修改的LLM与检索字段；下一请求生效，进行中的请求继续使用原快照。
- 回答与查询改写分别配置思考模式、思考强度、Temperature和最大完成Tokens；查询改写另有启停和独立超时。参数按调用用途区分，但不绑定某个具体模型名。
- 思考模式、思考强度和Temperature始终允许编辑；界面和保存响应提示上游可能忽略、不支持或重新解释组合，不以单个模型规则强制禁用字段。
- API Key支持保持、替换和清除；不得回填旧明文。
- 恢复部署默认，只移除运行时覆盖，不修改部署文件或重建向量库。
- 使用未保存草稿显式测试模型连接；必须提示会真实调用服务并可能产生费用。
- Trace记录settings revision、实际检索参数、LLM是否尝试调用、provider/model，以及回答/改写各自冻结的生成参数和调用状态。
- 旧Trace字段缺失时明确“未记录”，不能猜测为默认值。
- Trace时延区分检索、上下文组装、改写、LLM生成、引用提取、会话提交和服务端首字里程碑；`chat-v2`声明统一total及边界外提交，不用总耗时差值推断具体阶段。实现和兼容规则见[OPT-006](../优化/OPT-006-Trace计量拆分与首字延迟优化.md#plan)。

## 3. 输入输出与安全边界

输入为带版本的设置patch或连接测试草稿；输出是脱敏配置、更新revision、字段生效级别、兼容性提示、冲突或校验错误。明文Key只能存在于必要的输入与内存处理过程；不得进入普通SQLite设置、Trace或错误回显。`provider_default`表示不提交显式思考控制；明确模式由provider适配层转换，兼容端点拒绝参数时应显式失败，不能伪装成已生效。

当前系统没有认证与角色隔离，只适用于可信本地工作区。可配置模型地址也意味着服务端会发起请求；远程开放前需要认证和出站访问策略。

## 4. 本期不包含

Embedding模型/维度、设备、切分、路径等不作为动态设置开放；拒答门控在S7/V3-5前禁止启用；不承诺跨平台明文回退或多进程强一致热更新。本期不采集、展示或持久化模型原始思考文本；前端继续只显示最终回答正文。

<a id="acceptance"></a>
## 5. 验收条件

保存前后请求能看到不同revision；单次请求内回答/改写参数不漂移。关闭查询改写后，有历史的追问不得调用改写模型并应回退原问题；思考开启时Temperature控件仍可编辑。敏感422不回显Key；读取状态不加载模型；连接失败不暴露凭据。新旧Trace都能持久化、加载和幂等重放，旧Trace不得补造新生成参数。

关系：实现[DES-006快照与计量合同](../设计/DES-006-运行时设置与Trace.md#snapshot)，验证[TEST-005](../测试/TEST-005-设置与Trace回归.md#cases)。S01—S10已纳入2026-09-09全量自动化回归；这不替代真实外部服务、生产代理或人工浏览器验收。
