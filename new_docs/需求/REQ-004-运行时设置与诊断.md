## 1. 需求背景

用户希望通过设置页调整问答模型和检索策略，并能知道历史回答使用了哪次设置。直接让浏览器改写部署文件会混淆密钥、重启配置和请求级参数。

来源：[设置方案及S1—S6记录](../../docs/前端设置功能优化方案.md)。

<a id="requirements"></a>
## 2. 功能需求

- 查看有效配置、字段来源和运行状态，不泄露密钥、不因查看页面冷加载模型。
- 保存允许动态修改的LLM与检索字段；下一请求生效，进行中的请求继续使用原快照。
- API Key支持保持、替换和清除；不得回填旧明文。
- 恢复部署默认，只移除运行时覆盖，不修改部署文件或重建向量库。
- 使用未保存草稿显式测试模型连接；必须提示会真实调用服务并可能产生费用。
- Trace记录settings revision、实际检索参数、LLM是否尝试调用及provider/model。
- 旧Trace字段缺失时明确“未记录”，不能猜测为默认值。
- Trace时延应区分检索、上下文组装、改写、LLM生成、引用提取、持久化和用户可见首字里程碑；每个字段必须声明计时边界，不能用总耗时减已知字段推断未测阶段。新增字段和兼容规则按[OPT-006](../优化/OPT-006-Trace计量拆分与首字延迟优化.md#plan)评审后实施。

## 3. 输入输出与安全边界

输入为带版本的设置patch或连接测试草稿；输出是脱敏配置、更新revision、字段生效级别、冲突或校验错误。明文Key只能存在于必要的输入与内存处理过程；不得进入普通SQLite设置、Trace或错误回显。

当前系统没有认证与角色隔离，只适用于可信本地工作区。可配置模型地址也意味着服务端会发起请求；远程开放前需要认证和出站访问策略。

## 4. 本期不包含

Embedding模型/维度、设备、切分、路径等不作为动态设置开放；拒答门控在S7/V3-5前禁止启用；不承诺跨平台明文回退或多进程强一致热更新。

<a id="acceptance"></a>
## 5. 验收条件

保存前后请求能看到不同revision；单次请求内参数不漂移。敏感422不回显Key；读取状态不加载模型；连接失败不暴露凭据。新旧Trace都能持久化、加载和幂等重放。

关系：实现[DES-006快照](../设计/DES-006-运行时设置与Trace.md#snapshot)，验证[TEST-005](../测试/TEST-005-设置与Trace回归.md#cases)。S01—S08已纳入2026-09-09全量自动化回归；这不意味着S09/S10计量扩展已实现，也不替代真实外部服务验收。
