## 1. 用户场景

用户在浏览器中管理文档、限定检索范围、持续追问，并查看来源和诊断。刷新页面后需要保留历史；网络失败后不应重复提交同一问题或丢失服务端已完成结果。

来源：[前端流式方案](../../docs/superpowers/plans/2026-08-13-v2-phase-3-frontend-streaming.md)、[UX重设计](../../docs/superpowers/plans/2026-08-15-phase-3-frontend-ux-redesign-plan.md)、[历史反馈](../../docs/测试反馈记录.md)。

<a id="requirements"></a>
## 2. 功能需求

| 领域 | 要求 | 输入 → 输出 |
|---|---|---|
| 会话 | 新建、查看、改名、删除；有界历史和追问 | 问题与当前会话 → 持久化消息 |
| 流式 | 用户问题立即可见；逐步显示答案；停止与失败重试 | 请求 → 进度/答案/错误状态 |
| 思考 | 展示上游返回的思考，正文到达默认折叠且可手动展开；成功历史可恢复 | reasoning_delta → 独立思考区域，不混入正文 |
| 本轮检索来源 | 不论拒答或正文引用与否都展示有效最终来源，分正文已引用/未引用 | 本轮TopK与正文标记 → 来源卡片，原chunk高亮不变 |
| 并发 | 请求幂等，旧会话末尾冲突时重同步 | request ID与末尾ID → 原结果或明确冲突 |
| 标签 | 独立创建、层级重命名、删除、修改文档标签 | 标签路径 → 文档范围 |
| 上传 | 先选择与暂存，再确认上传；仅重试失败项 | 文件队列 → 逐文件状态/warning |
| 文档管理 | 名称搜索与标签筛选组合、预览、按ID删除 | 查询与筛选 → 文档列表 |
| 布局 | 检索范围靠近输入区；抽屉按需展开 | 桌面与窄屏 → 可用工作区 |

现状与边界（2026-09-09）：NDJSON逻辑事件顺序保持不变，BUG-004已通过原生异步LLM流和同步服务线程下放修复；真实本地TCP/uvicorn测试证明人工延迟delta在响应完成前逐行到达，前端测试证明首块到达即更新。由此确认本地自动化条件下满足“逐步显示答案”的传输要求；人工浏览器多视口、真实外部LLM首字时间和生产反向代理是否缓冲仍未验收。

## 3. 非功能要求

2026-09-19当前范围：上述思考展示、来源分组及预览定位已实现；多轮每轮检索，是否改写遵循已有开关，改写失败仍检索原问题。思考与引用定位的既往人工复测记录见[09-18优化记录](../../docs/2026-09-18-视觉与会话体验优化记录.md)；本次新增回归与未验证边界见[TEST-003](../测试/TEST-003-会话引用与流式协议.md#current-policy)。不要求其他服务商一定返回思考字段。

流结束、失败和停止必须有可区分状态；不得把客户端停止视作撤销已经完成的服务端事务。窄屏不能整页横向溢出；拖动面板不能遮住关键操作。持久化业务数据以服务端为准。

## 4. 不做什么

不在本轮引入用户账号、多租户、跨会话共享、工具调用Agent。旧Streamlit暂时保留用于兼容对照，删除需独立确认；这不意味着旧界面与React完全同等支持新功能。

<a id="acceptance"></a>
## 5. 验收条件

1. 刷新后消息、来源和启用时的Trace可恢复。
2. 重复request ID不重复生成；冲突重同步后能继续提问。
3. 上传失败队列保留，成功项不会在“重试失败项”中再次上传。
4. 标签父级包含后代、多标签并集；名称搜索与标签范围取交集。
5. 流式传输至少通过真实HTTP逐行读取；组件测试之外仍要进行真实浏览器多视口检查。

关系：协议见[DES-004](../设计/DES-004-会话流式协议与来源预览.md#contract)，交互见[DES-005](../设计/DES-005-标签与React交互.md#interaction)，验收见[TEST-003 会话引用与流式协议](../测试/TEST-003-会话引用与流式协议.md)和[TEST-004 标签与React交互](../测试/TEST-004-标签与React交互.md)。
