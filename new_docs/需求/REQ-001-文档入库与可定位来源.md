## 1. 需求背景与场景

知识库使用者需要把企业资料变成可检索内容，并从回答回到原文核对。原始资料包含真实页、逻辑页、章节、幻灯片以及扫描图片，不能一律当成无结构字符串。

> 本需求由现有实现和历史方案反向整理，不代表新增需求已获用户签核。原始依据：[v2设计](../../docs/superpowers/specs/2026-08-13-rag-v2-optimization-design.md)、[下一阶段设计](../../docs/superpowers/specs/2026-07-23-rag-next-stage-optimization-design.md)。

<a id="requirements"></a>
## 2. 功能需求

| 编号 | 要求 | 输入与输出 |
|---|---|---|
| R1 | 支持PDF、DOCX、TXT、Markdown、PPTX | 文件 → 稳定文档ID、入库状态与warning |
| R2 | 保留结构与格式特有定位 | 页/逻辑页/章节/幻灯片 → 可读位置标签 |
| R3 | 允许同名文件独立入库 | 同名上传 → 不同文档ID，不暗中覆盖 |
| R4 | 可选识别扫描页和内嵌图片 | 图片 → 带OCR标记的文本；识别失败可见 |
| R5 | 支持全文与引用预览 | 文档ID/引用 → 原序结构与命中高亮 |
| R6 | 失败可诊断、删除可追踪 | 失败记录与文档级清理，不影响其他文档 |

## 3. 非功能要求与边界

当前单文件上限为50 MiB；文件名不得携带路径。结构定位必须可复现，读取损坏数据应明确失败，不能悄悄切换到另一份来源。OCR应有调用预算与缓存，开关关闭时不调用视觉服务。

本期不包含Excel/NL2SQL、旧版DOC/XLS/PPT、完整Office版面复原、Markdown外链图片抓取、SmartArt、演讲者备注。OCR文字不是人工校对结果；warning降级不等于已成功识别图片。

<a id="acceptance"></a>
## 4. 验收条件

1. 五种格式各有结构、切分、定位用例；原文offset可回查。
2. 同名文档隔离；失败上传不会成为可问答的ready文档。
3. OCR关闭、失败、缓存命中、图片预览越界路径均有验证。
4. 删除、重建后引用状态明确，不能把失效引用指向其他内容。
5. 真实扫描件和外部视觉质量另做人工/外部验收，不以mock测试代替。

关系：实现方案见[DES-002结构契约](../设计/DES-002-结构化解析与OCR.md#contract)；验证见[TEST-001用例](../测试/TEST-001-解析入库与OCR.md#cases)。
