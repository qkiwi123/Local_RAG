## 1. 开发目标与来源

关系：实现[会话契约](../设计/DES-004-会话流式协议与来源预览.md#contract)与[流式协议](../设计/DES-004-会话流式协议与来源预览.md#stream)。将检索、生成和消息生命周期衔接，支持请求重放及明确失败。

## 2. 代码与输入输出

[chat.py](../../backend/routers/chat.py)：POST /api/chat与/api/chat/stream；
[conversations.py](../../backend/routers/conversations.py)：会话CRUD；
[conversation_store.py](../../backend/services/conversation_store.py)：请求与消息状态；
[conversation_context.py](../../backend/services/conversation_context.py)：有界历史；
[llm.py](../../backend/services/llm.py)：改写、回答和stream客户端。

请求字段包括question、conversation_id、request_id、expected_last_message_id、retry_failed、tags。同步输出ChatResponse；流式输出逐行JSON事件。

## 3. 核心流程

请求开始获取一次运行时snapshot → 建立/恢复持久化请求 → 读取有界历史 → 必要时改写独立问题 → 解析标签ID范围 → 检索 → 空结果短路或生成 → 提取引用 → 完成消息与保存可选Trace。2026-09-09后，流式模型生成使用`AsyncOpenAI`和`async for`；检索、历史/标签数据库访问、引用提取及消息/Trace持久化通过`asyncio.to_thread`移出ASGI事件循环。同步`POST /api/chat`中的检索、模型调用和持久化也采用相同下放边界。

同步与异步LLM客户端分别使用最多4项的缓存，但共享revision、provider、base URL、timeout和Key摘要派生规则，缓存键不含明文Key。普通与带历史的异步流入口复用现有消息合同，上游流在正常结束或中断时显式关闭。

重复已完成request ID重放首次答案/引用/Trace；409明确标识末尾变化、进行中或过期重试。LLM关闭时不做改写/回答调用。无检索结果返回固定提示；选择了标签时提示范围内没有相关文档。

## 4. 失败、停止与并发

流内retrieval_error或llm_error返回error事件；未完成的断开请求标interrupted，不保存半截助手答案。客户端Abort并不保证服务器尚未完成；重同步才是恢复事实的手段。应用启动会处理遗留pending请求。

## 5. 实际结果与测试

主链路、S6快照、BUG-004异步化和OPT-006方向一代码均已存在。真实本地HTTP用例证明人工延迟delta在响应完成前逐行到达，检索工作线程等待期间健康检查仍可响应；Trace阶段全量后端827项通过、3项跳过。验证见[TEST-003](../测试/TEST-003-会话引用与流式协议.md#cases)，配置/Trace见[TEST-005 设置与Trace回归](../测试/TEST-005-设置与Trace回归.md)。历史409与即时用户消息问题对应[反馈17/22](../测试/TEST-007-缺陷与历史反馈追踪.md#feedback)，UI实现由[DEV-008 React主前端](../开发/DEV-008-React主前端.md)承接。

## 6. 已知限制

当前多轮历史是有界文本，不是无限上下文记忆。没有账号权限隔离。流式路径部分耗时字段由当前实现填写为0，不能把0解释为实测没有花费；Trace计时解释见[DEV-010限制](../开发/DEV-010-检索Trace与配置追溯.md#limitations)。

同步阻塞和本地集中到达已由[BUG-004](../测试/BUG-004-流式响应缓冲至完成时一次性输出.md#regression)修复；`chat-v2`已补齐流式生成、改写、引用、会话提交和服务端delta里程碑。同步服务仍会占用默认线程池，外部LLM/模型计算耗时并未因此缩短；线程池容量、生产并发和浏览器实际首字尚无压测结论。查询改写策略仍按[OPT-006](../优化/OPT-006-Trace计量拆分与首字延迟优化.md#rewrite)搁置。
