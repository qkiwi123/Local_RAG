## 1. 开发目标

关系：实现[存储边界](../设计/DES-001-系统架构与存储边界.md#storage)和[DES-002 结构化解析与OCR](../设计/DES-002-结构化解析与OCR.md)，满足[REQ-001 文档入库与可定位来源](../需求/REQ-001-文档入库与可定位来源.md)。保证同名文档独立、入库状态可诊断，并支持不覆盖原索引的重建。

## 2. 涉及代码与接口

[upload.py](../../backend/routers/upload.py)提供POST /api/upload、GET /api/documents、按稳定ID删除和全文预览；[document_store.py](../../backend/services/document_store.py)管理processing/ready/failed；[unit_store.py](../../backend/services/unit_store.py)保存结构；[vector_store.py](../../backend/services/vector_store.py)写入/删除向量。

<a id="implementation"></a>
## 3. 入库流程与输入输出

1. 接收multipart file与可选tags，拒绝路径文件名和未注册后缀。
2. 读取内容检查50 MiB上限，分配独立document_id，写隐藏临时文件。
3. 创建processing记录，解析units/warnings，生成chunks。
4. 写结构单元、向量和标签，再os.replace临时文件到document_id.ext。
5. 标记ready，返回document_id、展示名、chunk_count及warnings。

同名文件生成不同ID，不覆盖。失败调用_cleanup_failed_ingest清理向量、结构/标签及临时文件，并尽力保留failed记录。此为补偿而非SQLite/Chroma跨库原子事务。

## 4. 删除与重建

按ID删除用于避免同名歧义，旧名称删除路由仅为兼容。源码仍有异常清理中的尽力处理；不能声称任何故障下都绝无孤立资产。

[scripts/rebuild_index.py](../../scripts/rebuild_index.py)拒绝源目标相同或目标非空；重新解析ready文档，核对chunk/unit对应、offset、数量、维度。校验新Chroma成功后仍会写指定metadata中的units，必要时更新chunk_count。因此“新索引目录”不等于“metadata只读”；安全操作见[OPS-002](../运维/OPS-002-数据备份恢复与索引重建.md#rebuild)。

## 5. 实际实现、测试与后续

实现与代码路径已核对；本次没有上传、删除或重建真实数据。回归覆盖在[TEST-001 解析入库与OCR](../测试/TEST-001-解析入库与OCR.md)与[TEST-009 本地运行与回滚验证](../测试/TEST-009-本地运行与回滚验证.md)。后续调整需检查上传整文件读取的内存占用、异常补偿和多资产一致性，不用单个成功HTTP响应代替完整生命周期验收。

## 6. 持久化BM25生命周期（P6-A业务联动已实现）

[OPT-005 P2](../优化/OPT-005-BM25持久化稀疏索引.md#phase-p2-result)已把BM25实现为可重建但必须验证一致性的派生索引，而不是SQLite/Chroma之外的新事实源。构建程序从显式、停写的语料副本生成新generation，记录有序chunk ID、正文摘要、metadata摘要、parser/chunker、分词器和参数合同；重新加载、文件hash、mmap、数量与oracle校验通过，且源指纹复核不变后才切换活动指针。

上传、删除改变Chroma前，活动BM25必须先持久标记为`dirty`。不得在上传事务中直接覆盖活动generation，也不得在查询线程同步全量重建。P6-A已在隔离存储中验证后台重建、并发切换和失败补偿。

实现入口为[sparse_lifecycle.py](../../backend/services/sparse_lifecycle.py)和[sparse_rebuild.py](../../backend/services/sparse_rebuild.py)。文档事务覆盖Chroma、SQLite提交及失败补偿，最外层退出后排队；实际写入前标脏失败则拒写，部分写入抛错仍使旧缓存失效。快照和最终发布使用同一事务锁，耗时构建在锁外；发布前核对revision、正文/metadata摘要和有效参数，并校验SQLite ready文档ID及逐文档chunk数。失败补偿不完整时保持dirty，不发布残余语料。

后台使用固定120题检验构建及mmap重载，启动时核对完整摘要，停机不再发布候选。空库保留dirty并停止重试；无活动指针必须先经受控入口建立首代。上述同步只覆盖单服务进程，外部脚本及生产构建仍须停写。独立Dense重建把Sparse路径隔离至新目标，且指定metadata仍会按第4节被写入。完整证据见[OPT-005 P6-A结果](../优化/OPT-005-BM25持久化稀疏索引.md#phase-p6a-result)。

全库Hybrid在dirty期间明确不可用；临时可用性只能由管理员显式切换Dense获得。自动静默回退、查询线程同步重建及继续读取上一代均不在P6范围。该方案及隔离测试先完成于P6-A，生产影子构建和默认切换分别停在P6-B/P6-C，见[OPT-005 P6协议](../优化/OPT-005-BM25持久化稀疏索引.md#phase-p6-plan)。

P6-B已于2026-09-08完成真实生产31篇/2620块的成套备份及恢复演练；辅助入口[verify_sparse_shadow.py](../../scripts/verify_sparse_shadow.py)复制整套资产、核对摘要并把服务路径限定在restore目录，完成两次mmap新进程及旧backend回滚。详见[OPT-005 P6-B结果](../优化/OPT-005-BM25持久化稀疏索引.md#phase-p6b-result)，生产C阶段未执行。

## P6-C本轮边界（2026-09-08）

生产31篇/2620块的同期GPU回归中，新旧BM25 Top50为120/120一致，副本Sparse P95从89.389ms降至7.732ms。旧版复测自身也出现Dense/最终排序变化，且历史文档已确认Chroma/HNSW新进程重放造成ANN状态波动；用户确认该非BM25因果项不阻断本次切换。生产active现为`ready`并指向`production-shadow-20260908-r1`，两次生产配置新进程Sparse P95为72.411/72.965ms，均低于旧版110%上限。默认配置和生产环境已切至`bm25s_mmap`，实现仍保留显式`rank_bm25_memory`回滚路径；检索算法本身未改。

证据：[P6-C生产启用报告](../../eval/crud_rag_1000/v3_1/bm25_persistence_p6c/README.md)及[最终结果](../../eval/crud_rag_1000/v3_1/bm25_persistence_p6c/result-20260908-r2.json)；历史Dense边界见[DES-007](../设计/DES-007-评测隔离与数据契约.md#dense-variance)。未执行外部LLM、浏览器、虚构生产写入或长期流量观察。

## Windows便携新库首代接入（2026-10-24已实现）

上文P6协议在源码部署中仍要求受控初代。W2按[OPS-005](../运维/OPS-005-Windows单人本地发布与初始化方案.md#sparse-bootstrap)和[DES-003](../设计/DES-003-检索融合与上下文选择.md#portable-bootstrap)新增便携分支：仅显式portable且当前根内工作空间首发未完成时，ready文档事务退出后触发首次generation。身份/运行兼容合同与首发日志保存在data/workspace.json，源码生产行为不变；已发布库缺指针不能被当作新库。提交窗口中断只能复核并重放日志指定候选，源不一致或文件损坏拒绝恢复，完整实现见[DEV-012 W2](./DEV-012-服务托管与启动停止.md#w2-result)。

复用现有锁、源摘要、SQLite逐文档核对、候选校验及原子发布，快照变化丢弃并重排，中断/失败不标ready；非空缺代/dirty期间Hybrid明确不可用，不在查询内构建或自动换后端。便携oracle从绑定快照最多32块抽取词组并加无匹配词、上限65查询，以portable-snapshot-v1及摘要记录；仍做构建与mmap的rank_bm25对照，不读eval题库，源码120题规则不变。后续上传/删除/重启沿用既有生命周期。新增单测和真实随包解释器合成资料验收见[TEST-009 W2](../测试/TEST-009-本地运行与回滚验证.md#w2-result)；没有上传或重建现有生产数据，完整W11产品矩阵仍按未完成范围记录。
