## 1. 开发目标与来源

关系：实现[文档契约](../设计/DES-008-文档治理架构.md#contract)和[REQ-007 文档治理与追踪](../需求/REQ-007-文档治理与追踪.md)。将可自动判断的文档结构问题作为失败返回，避免维护仅靠人工记忆。

## 2. 文件与调用

工具为[check_docs.py](../工具/check_docs.py)，只使用Python标准库；保护基线为[source_snapshot.json](../工具/source_snapshot.json)。不导入backend，不读取密钥明文到报告，不启动服务、不加载模型。

从仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe new_docs\工具\check_docs.py
.\.venv\Scripts\python.exe new_docs\工具\check_docs.py --check-preserved
```

需要保存审计报告时显式指定--report；工具限制写入本new_docs/工具目录。平时检查默认只读。--check-preserved仅用于本次整理验收，后续正常业务开发不应据此禁止代码变化。

## 3. 检查逻辑

1. 枚举本目录Markdown，排除代码围栏后解析实际链接和锚点。
2. 检查核心ID、文件名、元信息、状态、日期、关联区和变更记录。
3. 验证相对链接目标与Markdown锚点，拒绝文档内本机绝对路径链接。
4. 核对分类导航覆盖与顶层六入口。
5. 从关联区建立核心文档图，验证双向边、必要上游与连通性。
6. 可选重新计算源快照中的SHA-256，检查原文件存在且未改动。
7. 输出错误明细与非零退出码；可按需写JSON结果。

## 4. 实际实现与验证边界

本次工具实现与新文档一起交付；执行结果集中记录在[TEST-008 文档完整性验收](../测试/TEST-008-文档完整性验收.md)，不在多处复制易失效计数。工具自检使用内存中的受控缺陷副本，覆盖坏链接/锚点、重复ID、缺元信息、无导航和断向关系，不创建业务测试文件。

## 5. 限制与后续维护

检查器不是完整CommonMark解析器；当前支持本目录采用的行内Markdown链接与显式锚点/常见标题锚点，不用正则结果证明外部网站可访问。代码路径存在不等于API运行成功，也不能证明叙述无误。

使用规范见[OPS-004 文档维护与变更流程](../运维/OPS-004-文档维护与变更流程.md)；若新增链接语法，应扩展检查及自检再使用。源快照是固定历史证据，不自动覆盖更新以掩盖原文变动。
