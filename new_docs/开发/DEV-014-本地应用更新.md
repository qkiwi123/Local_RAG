## 1. 来源与交付

实现[REQ-006本地更新](../需求/REQ-006-本地运行与数据安全.md#offline-update)与[DES-001更新事务](../设计/DES-001-系统架构与存储边界.md#offline-update)。支持固定运行锁、模型、前端依赖和明确数据库版本的W4内部便携包；不是源码目录更新器。

[build_update.py](../../deploy/windows/build_update.py)收集完整应用层：backend、launcher、React构建、五个CMD、使用说明和资源清单。运行时、模型及原有许可资产与基包完全一致；数据/cache/logs/state/eval/Git不进入包。版本由应用文件摘要生成，清单声明支持的基包资源摘要、运行锁及数据版本。当前包含会话v5→v6迁移，旧文档和索引不因此重建。

## 2. 构建与入口

先执行web的lint/test/build，再运行维护者入口：

```powershell
.\scripts\build_windows_update.ps1 -BaseDirectory <匹配的完整便携目录> -Notes '本次更新说明'
```

输出遵循本机忽略的build/windows-release/output-preference.json，也可显式指定-Output。默认拒绝未提交源码，内部预览可显式-AllowWorkingTree；记录基准提交、工作区纳入标志和实际应用摘要，不把未提交内容冒充提交版本。不覆盖已有包；包旁JSON记录SHA-256、大小、基包/目标身份及说明。校验摘要证明完整性，不代表发行者签名；首版为手动选择可信来源的本地包，不自动下载或宣称公开发行认证。

- 首次接入旧版：将更新ZIP解压到独立目录，运行安装更新.cmd，选择当前便携目录并确认；使用旧目录自带Python，不要求另装环境。
- 已有更新功能：设置→关于与更新→选择本地更新包→检查版本/说明→备份并更新；或运行便携目录的更新.cmd选择ZIP。
- 恢复：若更新被中断，运行更新.cmd；首次旧版尚未装好该入口时，用解压包中的安装更新.cmd选择同一目录。根据更新记录恢复，保留备份与失败现场。

[update_entry.py](../../launcher/update_entry.py)、[update_ui.ps1](../../launcher/update_ui.ps1)及[安装更新脚本](../../deploy/windows/安装更新.cmd)提供双击入口；子PowerShell进程的执行策略参数不修改系统持久策略。原生文件/目录选择框使用Windows Forms，实际引擎命令行和网页入口的验证边界见[TEST-010](../测试/TEST-010-本地应用更新验收.md)。

## 3. 事务、数据与恢复

[updater.py](../../launcher/updater.py)阶段为staged→queued→stopping→backing_up→backed_up→applying→starting→completed。检查只读取包元信息/摘要，不执行包中代码；拒绝损坏、路径逃逸、重复/Windows别名、未知载荷、保护目录、错误基版本/运行锁/数据库及重复目标版本。

独立worker从已信任当前引擎复制到state/updates/<事务>/runner运行；启动/停止沿用[DEV-012](./DEV-012-服务托管与启动停止.md)的实例身份和文件锁。等待任务正常结束，更新不自动强制杀进程。持久化活动记录阻止普通启动进入混合版本。正常网页更新保留原监听端口；端口冲突或启动失败进入恢复。

停服后备份被管理的程序文件和完整data，逐文件核对摘要，完成标记写入后才替换。原模型/运行时/许可文件不在替换白名单；废弃的旧应用文件移到事务目录保留，未知文件不作为清理目标。数据/目录链接拒绝处理，空间不足在替换前报错。

新版本验证完成前，[UpdateMaintenanceMiddleware](../../backend/services/update_maintenance.py)暂停业务写请求，仍允许健康、状态和页面读取。避免新版本尚未验收时接收用户写入，随后恢复备份造成丢失。启动检查包含匹配的资产/前端/进程健康、模型预热和SQLite完整性；已成功完成后才清除活动标识。

异常且尚未替换时保留原程序/数据，不为恢复重复停止现有服务。已经替换时先停候选实例，核对备份，恢复旧程序；若启动阶段可能迁移了数据，恢复整套data而非只换SQLite，并把候选数据保留到failed-data目录。恢复失败保持recovery_required和启动保护，可修复条件后再次恢复。数据首次恢复完成后先持久化data_restore_complete，再恢复旧启动器；恢复本身被中断时再次执行不重复回退已经恢复的数据，避免旧版重新打开后新增内容被旧快照覆盖。不承诺已完成更新之后的任意无损降级。

事务备份在state/updates中，用于本次更新失败恢复，删除整个便携目录也会删除它；它不替代[OPS-002外部备份](../运维/OPS-002-数据备份恢复与索引重建.md)。不自动删除历史事务和备份。

## 4. API与界面

[local_update.py](../../backend/routers/local_update.py)：GET /api/local-update/status；POST /api/local-update/inspect接收ZIP但不执行；POST /api/local-update/{id}/apply在确认后派发独立worker。仅便携模式允许检查/应用，复用Host/Origin限制，不接受客户端指定安装根。上传有64 MiB压缩限制和256 MiB展开上限。

[LocalUpdateCard.tsx](../../web/src/pages/settings/LocalUpdateCard.tsx)展示版本、更新说明、二次确认、重启期间等待、完成刷新和恢复提示；后台暂时离线时不会自动重复提交。源码模式仅显示说明。设置表单草稿与更新入口分开，选择ZIP不保存设置。
