## 3. 数据结构、提交与生效

部署默认＋SQLite非敏感覆盖＋DPAPI Key → EffectiveSettingsSnapshot。请求开始冻结，保存后的下一请求生效；进行中的请求不变。revision从数据库保存记录取得，expected_revision防止陈旧更新覆盖新值。

Key不在SQLite普通payload中；DPAPI密文默认与metadata.db同目录，文件名runtime_secrets.bin。运行时Key优先于环境Key，清除运行时Key后可以回退环境Key；若LLM仍启用但无任何可用Key，修改被拒绝。

保存流程先完成字段及跨字段验证。恢复默认不改.env、不重建Chroma；密钥操作与SQLite失败有恢复路径，详细失败用例见[test_runtime_settings.py](../../tests/test_runtime_settings.py)。DPAPI不可用时拒绝写入。

## 4. API与UI流程

读取settings/runtime-status不触发模型冷加载；PATCH与reset返回新revision；test-llm使用未保存草稿。设置页保持/替换/清除Key三态，不回填明文、不在localStorage保存业务配置。连接测试是唯一显式测试动作，可能发出真实请求。

## 5. 实际结果、历史与限制

当前分支代码已包含S1—S6相关实现；工作树中本次新增/修改的是文档，不能把文档更新写成设置功能代码提交。本次未保存设置或调用连接测试。实现证据来自[设置方案实施记录](../../docs/前端设置功能优化方案.md)，验证见[TEST-005 设置与Trace回归](../测试/TEST-005-设置与Trace回归.md)。

无认证、无多租户；任意模型地址带来服务端出站请求风险。多worker配置传播没有本轮保证。Embedding/切分/设备不是动态白名单；拒答gate保持不可用。
