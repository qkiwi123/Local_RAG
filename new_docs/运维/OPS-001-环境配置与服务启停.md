## 1. 运维目标与前提

本文描述当前源码方式，需要自行准备Python、Node.js及模型缓存。2026-10-03用户确认的[OPS-005](./OPS-005-Windows单人本地发布与初始化方案.md)修订为GPU优先/CPU备用便携ZIP：运行时、两份模型和React随包，两种模式保留Hybrid/持久化BM25/重排，所有应用资产在解压目录。首版只提供启停/基础维护，备份升级先人工复制；新便携库首代自动构建待实现。拟定CMD入口尚不存在，下述源码安装和首代CLI仍按现有协议使用，不是未来便携用户必做步骤。

## 2. 环境与安装

后端依赖以[requirements.txt](../../requirements.txt)为准，旧CPU环境为.venv，GPU为.venv-gpu；前端以[package.json](../../web/package.json)和lockfile为准。仓库记录Python 3.14已用过，但本次未重装验证。

CPU环境的准备示例（在根目录，使用已安装Python）：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path -LiteralPath .env)) { Copy-Item -LiteralPath .env.example -Destination .env }
```

以上仅创建依赖环境，不保证新电脑已具备完整运行条件。不要在已有环境里盲目重装GPU PyTorch。GPU历史组合见[OPT-002 CPU到GPU检索迁移](../优化/OPT-002-CPU到GPU检索迁移.md)；新机器需按硬件另行验证。BGE和Reranker是local_files_only加载，运行前准备本地缓存；只设置HF_HUB_OFFLINE=0不会让现有解析函数自动下载。首次启用LLM需真实环境Key或可读DPAPI Key；不使用LLM时设LLM_ENABLED=false，占位Key不能用于真实请求。

源码.env.example目前含bm25s_mmap与既有生产语料标识，复制后不能视为全新用户配置。新空库暂可显式选rank_bm25_memory并清空生产语料标识；持久化后端需先按[OPS-002](./OPS-002-数据备份恢复与索引重建.md#rebuild)准备匹配的首个活动代。可信本机需要原文预览时显式设CITATION_PREVIEW_ENABLED=true。已有库不可为了照此示例覆盖原.env或切后端。

## 4. 构建、启动和停止

首次在web目录执行npm.cmd ci和npm.cmd run build；回到根目录：

```powershell
.\scripts\start.ps1
.\scripts\start.ps1 -InferenceProfile cpu
.\scripts\start.ps1 -Reload
```

以上是三种替代选择，不要连续执行。默认gpu；2026-09-21按当前脚本核对，源码启动每次重新构建React并等待模型预热，默认只启动React托管后端，打开带缓存戳的8000页面。旧Streamlit仅显式-LegacyFrontend时启动；-NoBrowser关闭自动打开浏览器。后续发布入口直接使用预构建产物，不改变这里的开发使用方式。

```powershell
.\scripts\stop.ps1
```

等价入口为start.ps1 -Stop。脚本受执行策略限制时可在确认信任后使用powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1；无需永久修改执行策略。

2026-10-24源码stop.ps1的两处PID创建时间判断改为绝对差，避免晚于保存时间的其他PID被单向比较误认；语法检查通过，未在生产服务执行。便携模式另有独立四个CMD，不需要更改PowerShell策略；真实本机链路、维护范围和当前原型位置见[W3说明](../../deploy/windows/W3.md)及[TEST-009 W3](../测试/TEST-009-本地运行与回滚验证.md#w3-result)，不可将源码目录当便携包直接运行。
