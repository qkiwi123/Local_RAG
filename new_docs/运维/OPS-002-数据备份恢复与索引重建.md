## 1. 运维对象与安全目标

关系：维护[DEV-002 上传与索引生命周期](../开发/DEV-002-上传与索引生命周期.md)的文档与索引、[DEV-003 OCR识别与原图预览](../开发/DEV-003-OCR识别与原图预览.md)的OCR资产及[存储契约](../设计/DES-001-系统架构与存储边界.md#storage)。保证原文、unit、chunk和配置可以对应，不只复制一个SQLite文件就声称完成备份。

## 2. 备份清单与前置条件

| 数据 | 备份考虑 |
|---|---|
| metadata.db | 包含文档、unit、会话、标签、Trace和运行设置；停写并处理SQLite WAL一致性 |
| Chroma目录 | 向量、文本、元数据整体一致 |
| BM25 generation、active指针与manifest | 与同一Chroma/SQLite快照成套保存；P6-B已创建生产影子代，生产active仍不存在 |
| uploads | 按document_id命名的原始文件，重建必需 |
| OCR_IMAGE_DIR | 引用到的原图；缺失时不能靠文字恢复 |
| VISION_CACHE_DIR | 可选派生缓存，但含敏感文字且丢失可能增加API成本 |
| runtime_secrets.bin与环境配置 | 受控保存，不进Git；DPAPI跨用户/机器未必可解密 |
| 代码、依赖、构建、参数与hash清单 | 确定恢复到哪个版本 |

先停止写入并确认相关服务退出，再备份整个一致集合；无法停写时需要专门一致性快照方案，本仓库未提供。P6-B已按用户阶段授权把成套备份保留在项目Git忽略的data/backups目录，没有配置自动清理；具体位置和摘要见第6节。

<a id="rebuild"></a>
## 3. 安全索引重建

1. 保留原始数据和配置，复制metadata到隔离工作目录；记录源/目标绝对解析路径供人工核查。
2. 为新Chroma选择不存在或空目标，不能与源相同。
3. 显式传--metadata-db副本、--upload-dir原文来源、--source-index-dir原索引和--target-dir新索引。
4. 确认OCR是否启用；重解析可能调用视觉API、写缓存/图片，隔离这些目录并另行确认费用。
5. 校验总量、逐文档chunk数、维度、unit/offset、引用预览、标签与会话。
6. 通过后才在停服窗口切换整套一致数据；原目录保留供回滚。

示例只展示参数形态，替换占位路径后才能执行：

```text
python scripts/rebuild_index.py --source-index-dir <旧Chroma> --target-dir <新Chroma> --metadata-db <metadata副本> --upload-dir <原文目录>
```

**脚本会在新索引校验后替换指定metadata中的结构单元。** --accept-chunk-count-change允许数量变化并更新登记值，不是“忽略校验”或默认必加。新目标目录不能保证主metadata不受写入；实现见[DEV-002 上传与索引生命周期](../开发/DEV-002-上传与索引生命周期.md)。

P2的[隔离构建命令](../../scripts/rebuild_sparse_index.py)要求显式传入源Chroma、源SQLite、目标、语料ID、chunk合同、oracle题库和报告路径，默认拒绝项目生产数据目录。Sparse先写新generation，验证manifest、有序chunk ID摘要、正文摘要、参数、mmap和兼容oracle，删除工作快照并复核源指纹后再切换活动指针；不能在原generation上覆盖写，也不能因Dense重建成功就默认Sparse同步成功。该命令只完成隔离基础能力，不等同于生产恢复流程。

P6-A已实现受控入口：须同时传入`--allow-production`和`--production-confirm <生产Chroma绝对路径>`，三条源/目标路径与环境变量优先后的配置精确匹配；`corpus-id`须以`production-`开头并提供120题oracle。生产构建仍必须停写，先核对SQLite `quick_check`、逐文档ID/chunk计数、parser/chunk/tokenizer/BM25合同及容量，再备份成套资产。脚本把SQLite WAL纳入前后摘要，构建及mmap重载均校验oracle；源变化不发布，报告不能覆盖已有文件或写入源/索引关键位置。默认不带`--publish`，只构建影子代。评测r5/r6不能直接成为生产generation。

`SPARSE_AUTO_REBUILD=true`仅在显式选择`bm25s_mmap`时生效；无active返回`needs_initial_generation`，不能靠上传绕过首次发布。重建状态由运行状态接口返回，空库为`empty`且active保留dirty；错误时退避重试。只支持单服务进程的事务协调；多个服务进程或外部写库脚本必须停写协调。P6-A仅在临时目录模拟生产配置验证入口，未运行真实生产构建或备份恢复，详见[阶段报告](../../eval/crud_rag_1000/v3_1/bm25_persistence_p6a/README.md)。

生产影子generation在P6-B只构建不启用：须通过manifest、逐文件hash、chunk/正文/metadata摘要、mmap、120题查询oracle、源前后不变及隔离成套恢复。P6-C才先原子发布活动指针，再写入匹配的`SPARSE_BACKEND=bm25s_mmap`、root和corpus ID；`RETRIEVAL_MODE=hybrid`不变。详细停止点见[OPT-005 P6协议](../优化/OPT-005-BM25持久化稀疏索引.md#phase-p6-plan)。

## 4. 恢复、升级与回滚

先恢复到新隔离目录，不覆盖原数据；采用匹配代码/模型/parser/配置，验证健康、文档数、引用、标签、会话和设置。DPAPI恢复失败时重新配置Key，不降级明文。确认后停服切换环境路径，再做冒烟。

回滚应恢复匹配的代码、metadata、Chroma和资产集合；持久化BM25实施后还需恢复匹配的generation、active指针和manifest。只切旧向量库而保留新unit或新BM25可能令检索与历史引用错位。旧程序不一定能读取schema v4，不承诺自动降级数据库。

## 5. 常见故障与结论

缺上传原文无法完整重建；维度不同不能复用旧索引；旧审核包或citation失效应检查parser/hash而非随意改ID。视觉缓存清理需评估再调用费用，规划见[OPT-004 视觉缓存容量治理](../优化/OPT-004-视觉缓存容量治理.md)。

P6-B已提供受控分阶段备份/恢复辅助工具并完成本机隔离演练，见第6节；不等同于自动定时备份、跨机器灾难恢复或全部[O05/O06](../测试/TEST-009-本地运行与回滚验证.md#cases)业务界面验收。

P3已使BM25索引损坏、缺失、dirty或合同错配显式失败，并在运行状态中区分状态；不自动退回查询时全库`rank_bm25`构建。P6方案允许管理员在维护/重建窗口显式切换Dense，并要求配置revision、Trace和状态可见；这不是自动降级。完整策略见[OPT-005 BM25持久化稀疏索引](../优化/OPT-005-BM25持久化稀疏索引.md#index-contract)。

P4在隔离副本上验证了mmap三轮各24题、4线程并发读共72/72一致；每进程只加载一次，关闭后索引映射数为0，源Chroma/SQLite与r5/r6索引前后hash不变，旧`rank_bm25_memory`三轮均可恢复运行。当前根目录为保留r5/r6回滚的约8.13 MiB，单代约4.06 MiB。以上只证明固定只读评测的可恢复性，不替代生产停写切换、备份恢复、上传联动或灾难演练。

## 6. P6-B生产影子与恢复演练（2026-09-08）

已在停写窗口按第2节创建成套备份`data/backups/p6b-20260908-r1/backup`，93,705,597字节；环境配置只保留于Git忽略目录。真实生产为31篇ready/2620块，5条failed记录不纳入构建；SQLite quick_check/schema 4、Chroma逐文档计数、原文和11个标签范围核对通过。初始Sparse目录与运行时密钥文件不存在，缺失状态也记录在备份清单。

独立影子位于`data/sparse_index/generations/production-shadow-20260908-r1`，生产active尚不存在。恢复先复制整套资产并比对摘要，再仅在本轮restore目录启用候选；两个mmap新进程和一个旧backend回滚新进程验证ASGI启动/关闭、120题四档结果、标签接口、并发、候选切换及句柄释放。最终源与原始备份摘要均不变，服务保持原有停止状态。没有覆盖原库、改生产`.env`或启用P6-C。

辅助入口[verify_sparse_shadow.py](../../scripts/verify_sparse_shadow.py)按阶段拒绝覆盖备份/报告、禁止恢复服务使用restore外路径；其运行清单包含私有文件路径，不提交Git。实际证据见[P6-B报告](../../eval/crud_rag_1000/v3_1/bm25_persistence_p6b/README.md)。本演练不代表跨机器DPAPI恢复、浏览器端验收或完整GPU/LLM服务验收；P6-C执行前需再次核对当前源与影子摘要，变化则重建。
