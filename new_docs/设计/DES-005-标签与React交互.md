## 1. 来源需求与设计目标

关系：实现[REQ-001 文档入库与可定位来源](../需求/REQ-001-文档入库与可定位来源.md)的文档管理及[REQ-003 会话与知识库交互](../需求/REQ-003-会话与知识库交互.md)的检索范围与界面交互。将知识库范围设定和会话输入放在用户容易理解的位置，避免上传/标签面板长期挤占文档列表。

<a id="tags"></a>
## 2. 标签数据模型与查询

SQLite保存tags与document_tags，tag_path用斜杠表达层级。选父级包含子孙，多选标签取并集；名称q与标签范围取交集。独立创建空标签不挂文档；删除标签只解除关联，不能删除文档。

标签先解析为allowed_document_ids，再进入Dense/BM25检索；不为标签修改重写Chroma的每条chunk。重命名子树需更新标签与关联并保持完整性，非法路径拒绝。

2026-10-23细化：一次多选/拖拽按批入队，真实拒绝原因采用单条可折叠提示，明细在有限高度内滚动。知识库概览统计当前列表，文件名可直接打开预览。设置页提供检索/模型/视觉/状态分区导航，BM25与Dense召回数量同级可见；已保存摘要与随草稿变化的流程预览分别标明。窄屏导航保持可达、保存栏和表单纵向排布；全局配色、字号层级、格式图标和对话空态统一。实现见[DEV-008](../开发/DEV-008-React主前端.md#implementation)，本轮范围见[TEST-004](../测试/TEST-004-标签与React交互.md#batch-selection)。

## 4. 接口、异常与兼容

主要接口由[DEV-007 标签与知识库管理](../开发/DEV-007-标签与知识库管理.md)记录；API客户端见[client.ts](../../web/src/api/client.ts)，NDJSON解析见[stream.ts](../../web/src/api/stream.ts)。409触发服务端重同步，上传失败不能通过简单刷新抹掉待重试项。

业务配置不写localStorage；面板宽度等UI偏好与业务配置区别管理。旧Streamlit仍保留，但React是主要验收入口。

2026-10-24：日夜主题属于本地UI偏好，第一次使用按系统主题初始化，显式切换后记住选择；页面、弹层和预览同时适配。检索范围在本日后续迭代改为输入区内的紧凑工具按钮，点击打开可搜索的扁平列表，多选即时生效；已选项可直接移除，一键恢复全部资料，没有额外完成步骤。叶子名称配父路径与文档计数，选中父标签时合并冗余子项并标明继承包含；先移除父项后可单独选子项。

上传的选择文件与确认队列合并，确认/重试/清空操作始终位于顶部；只滚动文件区域。每批结束自动清理成功项，失败项可重试，新增暂存项不受影响；成功项处理警告由独立摘要保留。一键清空属于移除本地暂存，不调用文档删除接口，上传期间不可用。实现与检查见[DEV-008](../开发/DEV-008-React主前端.md#implementation)、[TEST-004](../测试/TEST-004-标签与React交互.md#theme-upload-workflow)。

<a id="chat-composer"></a>
### 对话空白态与输入区

空白会话以简短欢迎标题配中下部输入区为中心，移除三步教学卡。输入草稿不改变位置，首次发送、流式或错误结果出现时转到底部输入；已有消息直接用对话布局。时间线、输入区和下方弹性留白共同布局，留白flex-grow以420 ms过渡，复用同一输入框以保留焦点和草稿；减少动画偏好禁用过渡。资料快捷入口与发送/停止按钮置于输入框内同一工具栏，中文输入法确认候选字不视为提交。实现和验证见[DEV-008](../开发/DEV-008-React主前端.md#chat-composer)、[TEST-004](../测试/TEST-004-标签与React交互.md#chat-composer)。

引用列表必须受所在阅读列宽度约束：文字可收缩，长文件名/位置换行，摘要限制两行，预览按钮保留独立列；620 px以下按钮移到下一行，不能依赖整页横向裁切隐藏溢出。此约定不改变已引用/未引用分组、原编号与预览目标；实际历史会话回归见[DEV-008](../开发/DEV-008-React主前端.md#citation-layout)、[TEST-004](../测试/TEST-004-标签与React交互.md#citation-layout)。

<a id="answer-column"></a>
### AI回复阅读列

AI回复不再使用气泡边框、底色、圆角和内部留白，用户问题保留气泡。正文、思考、引用及检索详情均受同一个最大920 px阅读列约束，输入框使用相同列宽；时间线和输入区同时预留滚动条槽，避免长回答出现滚动条后横向偏移。桌面正文15 px/1.85行高，窄屏14 px/1.8，轮次间距28 px；引用区以细分隔线和留白区分正文，长路径和预览按钮继续遵循局部宽度约束。空白欢迎态与发送后移动沿用此前契约。实现及证据见[DEV-008](../开发/DEV-008-React主前端.md#answer-column)、[TEST-004](../测试/TEST-004-标签与React交互.md#answer-column)。

<a id="conversation-followup"></a>
### 2026-10-24会话与布局后续合同

“新建对话”是本地空白视图，清空当前选择和输入，首次发送才调用创建及流接口；sessionStorage用`new`区分显式空白页与尚未选择的默认页。生成状态按会话/独立草稿key隔离，历史切换或新建只改变可见视图，原请求继续生成并正常保存。返回正在生成的会话恢复进度；返回已经完成的会话读取完整历史。不同会话请求独立，同一会话防重复；创建未返回时切走也不丢弃原问题或抢回视图。历史读取和列表刷新仍用序号防止迟到覆盖。创建与流仍为两个接口，不自动删除已有会话或改写旧历史。

此前“切换即abort”的合同已撤销：只有明确停止当前生成、用户删除对应会话或组件卸载才中止该连接；跨历史/新空白页导航不等同取消。刷新/关闭页面等真实断连仍采用原失败合同，不外推为跨页面生命周期的服务端后台任务。原因及验收见[DEV-008](../开发/DEV-008-React主前端.md#conversation-return)、[TEST-004](../测试/TEST-004-标签与React交互.md#conversation-return)。

会话栏的新建按钮和会话条目放在同一个滚动容器内，共用滚动条占位及内容边界，新建操作在该容器顶部保持可达。用户消息四角12 px；输入区桌面四角22 px、窄屏18 px并使用对称横向留白。来源用可键盘操作的按钮默认收起，展示片段数，展开才渲染原来源分组，保持来源编号与原文定位。

AppShell从健康接口读取`runtime.port`，该值来自服务端连接scope，不使用浏览器地址或转发头推断；每30秒刷新端口/在线状态，失败显示未知，旧版本缺字段不编造端口。390 px设置导航采用两行，顶部保留三个主导航及紧凑主题/端口/在线指示。实现及测量见[DEV-008](../开发/DEV-008-React主前端.md#conversation-followup)、[TEST-004](../测试/TEST-004-标签与React交互.md#conversation-followup)。
