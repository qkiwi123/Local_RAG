<a id="contract"></a>
## 2. 查询选择契约

```text
问题 + allowed_document_ids + 冻结配置
  → Dense（编码 → 向量TopK → distance阈值）
  → BM25（独立TopK、k1、b）
  → 按mode选择单路，或RRF融合
  → 可选Reranker（只取精排candidate K）
  → 单文档配额
  → final TopK
  → 来源编号上下文
```

[retriever.py](../../backend/services/retriever.py)的RetrievalRuntimeConfig为不可变dataclass；_runtime_config统一实际参数；_retrieve_internal负责共享主流程。标签ID范围在召回时传入，两条分支语义必须一致：None表示不限制，空集合表示无可检索文档。

检索输入说明：首轮问题直接作为检索输入；持久化追问在检索前可能由`rewrite_followup`生成`standalone_question`，最终回答仍保留原问题和有界历史。DeepSeek改写调用显式关闭思考并通过严格提示词保持对象和比较范围；失败仍回退原问题。当前实现不提供“确认无指代就跳过改写”的判断，也不提供改写模式运行时开关；短样本证据与长期观测边界见[OPT-006](../优化/OPT-006-Trace计量拆分与首字延迟优化.md#rewrite)。

## 3. 参数与分数不可混用

| 项目 | 语义 | 作用点 |
|---|---|---|
| dense_candidate_k | Dense前级窗口 | 阈值之前的向量候选 |
| dense_distance_threshold | cosine distance上界，越小越严格 | 仅Dense分支 |
| bm25_top_k/k1/b | 词法窗口与打分参数 | BM25 |
| rrf_k | 排名融合平滑常数 | Hybrid融合，不是返回数量 |
| fusion_pool_k（派生值） | max(Dense K, BM25 K, 重排K；重排关闭则final K) | 当前没有独立配置字段，不是已经完全解耦的实验维度 |
| reranker_candidate_k | Cross-encoder输入上限 | 融合或单路候选之后 |
| final_top_k | 最终上下文数量上限 | 排序和单文档配额之后 |
| max_chunks_per_document | 同文档上限 | 最终选择 |

RRF按排名融合，不把Dense距离和BM25分数直接相加。精排分数也不是概率。未启用校准门控时，低精排分仍可能被选中。

## 4. 数据、缓存与性能

BM25来自Chroma中的文本投影，缓存位于进程内；语料变更和k1/b变更需刷新对应缓存，不写回向量。BGE/Reranker本地加载，设备与精度由部署配置决定；模型缓存缺失不是自动联网下载的理由。

Trace只记录实际执行的候选与参数，不反推设置草稿。关闭Trace不应改变候选选择。

## 5. 取舍、限制与后续开发

固定候选窗口与单文档配额能控制延迟和上下文长度，也可能淘汰相关证据。Hybrid曾在小样本中无增益并降低不可回答短路率，历史决策见[OPT-001](../优化/OPT-001-历史检索优化与Hybrid决策.md#hybrid)；这不是所有语料上的通用结论。

当前refusal gate不可启用，待[OPT-003 候选深度与拒答门控](../优化/OPT-003-候选深度与拒答门控.md)校准；不可用单题阈值修补替代完整评测。实现[DEV-004 检索与模型推理](../开发/DEV-004-检索与模型推理.md)与[DEV-010 检索Trace与配置追溯](../开发/DEV-010-检索Trace与配置追溯.md)；验证[TEST-002 检索质量与性能](../测试/TEST-002-检索质量与性能.md)。算法调整必须同步此契约、Trace解释和评测配置。

## 6. V3-5实验与业务改造边界

2026-08-28基线显示一题的第二gold已进入Dense第15名且通过阈值，却在RRF截断后消失，证据见[TEST-002](../测试/TEST-002-检索质量与性能.md#baseline-v31)。
因此参数实验必须记录派生融合池，不能把扩大Dense K的结果全部归因于Dense本身，或把RRF常数60当成60个候选。

本轮主方案先在现有实现上做模式、前级、重排和配额实验，不改变算法。独立fusion窗口是证据驱动的后续分支，不预先添加未生效字段。
离线query级分数/跨路门控只属于实验策略，不改变以上现行流程。若用户确认S7落地，需先明确门控位置、空结果/过滤原因、配置验证及上下文选择合同，再实现并做Trace/API回归。
对应实现待办由[DEV-004](../开发/DEV-004-检索与模型推理.md#tuning-boundary)记录，候选值和停止点见[OPT-003](../优化/OPT-003-候选深度与拒答门控.md#plan)。

<a id="persistent-bm25"></a>
## 7. BM25持久化设计与P3实现

P3已在不改变第2节检索选择顺序的前提下增加部署级可选实现：默认仍用进程内`rank_bm25`；显式选择`bm25s_mmap`时，全库BM25从预构建磁盘索引生成候选，只分词问题、mmap读取TopK，再按稳定`chunk_id`批量回取Chroma正文与metadata，之后继续使用现有RRF、Reranker和最终配额。

活动generation必须由manifest绑定有序chunk ID摘要、正文摘要、parser/chunker、中文分词器及词典、BM25实现和`k1/b`。P1还证明必须记录`method=atire`、自定义`idf_method=rank_bm25_robertson_epsilon`及与`rank_bm25 epsilon=0.25`一致的负IDF下限；BM25S原生配置不等价。构建新generation后先重新加载和校验，再原子切换活动指针；查询请求不得隐式全量重建。Chroma或文档发生增删后，词法索引进入`dirty`，评测请求直接中止；业务是否显式降级Dense需另行授权并写入Trace。

范围语义保持不变：`None`使用合同匹配的全库持久化索引，空集合立即返回空结果，非空集合首期沿用当前过滤后子语料BM25。全库TopK后过滤既可能漏掉范围内候选，也改变当前IDF语义，不属于等价实现。完整方案、备选技术和停止点见[OPT-005 BM25持久化稀疏索引](../优化/OPT-005-BM25持久化稀疏索引.md#architecture)。

P4没有改变该数据流，只在隔离副本上测量两种backend。同期结果显示Sparse暖态均值由20.700降至5.630毫秒，但完整暖态均值只由354.806降至342.947毫秒；主要瓶颈仍是约311毫秒的Reranker。设计判断因此不能只看Sparse百分比：P5需同时权衡约3.3%的端到端收益、单代约4.06 MiB派生索引、动态一致性复杂度和既有不可回答缺陷。独立GPU进程的Dense顺序波动由P3同Dense候选回放隔离，不修改融合合同。

P5方案选择`bm25s_mmap`作为生产Sparse默认，但不改变第2节数据流和当前`RETRIEVAL_MODE=hybrid`。P6采用“写前持久标脏 → 完成文档事务 → 合并后台全量构建 → 发布前复核源revision/摘要 → 原子切换generation”的状态机。`dirty/missing/corrupt/mismatch`期间，全库Hybrid fail-closed；管理员可显式切换Dense，系统不得静默使用旧generation或内存BM25。现有进程内Chroma revision只处理单进程缓存，不能代替跨重启的持久dirty状态。

初次上线必须使用生产一致快照创建独立影子generation，不能复用评测r5/r6。先完成恢复和旧backend回滚演练，再发布活动指针和默认配置；具体三段停止点见[OPT-005 P6](../优化/OPT-005-BM25持久化稀疏索引.md#phase-p6-plan)。若动态写入导致重建窗口不可接受，再另行评估增量倒排服务，而不是在本次切换中直接引入Milvus。

2026-09-08 P6-A已实现该状态机。文档事务、查询评分/正文回取及最终复核/发布在单服务进程内互斥，全量构建在锁外执行；后台绑定有效运行时k1/b、源revision和正文/metadata摘要。SQLite ready文档ID及逐文档块数不一致时不得发布；缓存清理不改变已验证revision。启动恢复先持久失效再核对完整摘要，无初代禁止自动引导，空库保留dirty并等待后续写入，停机不发布候选。验证范围及并发限制见[OPT-005 P6-A结果](../优化/OPT-005-BM25持久化稀疏索引.md#phase-p6a-result)。

## P6-C本轮边界（2026-09-08）

生产31篇/2620块的同期GPU回归中，新旧BM25 Top50为120/120一致，副本Sparse P95从89.389ms降至7.732ms。旧版复测自身也出现Dense/最终排序变化，且历史文档已确认Chroma/HNSW新进程重放造成ANN状态波动；用户确认该非BM25因果项不阻断本次切换。生产active现为`ready`并指向`production-shadow-20260908-r1`，两次生产配置新进程Sparse P95为72.411/72.965ms，均低于旧版110%上限。P5条件采用现已生效；Dense、RRF、Reranker和Hybrid参数不变，旧后端仍可显式回滚。

证据：[P6-C生产启用报告](../../eval/crud_rag_1000/v3_1/bm25_persistence_p6c/README.md)及[最终结果](../../eval/crud_rag_1000/v3_1/bm25_persistence_p6c/result-20260908-r2.json)；历史Dense边界见[DES-007](../设计/DES-007-评测隔离与数据契约.md#dense-variance)。未执行外部LLM、浏览器、虚构生产写入或长期流量观察。
