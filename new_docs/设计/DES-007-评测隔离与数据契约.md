<a id="isolation"></a>
## 3. 执行与隔离

CLI在导入backend前设置独立CHROMA_PERSIST_DIR、METADATA_DB_PATH和UPLOAD_DIR；[adapters.py](../../eval/adapters.py)做隔离断言。固定label、模型、parser、候选参数、设备和精度；保留逐题JSONL、汇总JSON/Markdown与配置来源。

run生成回答，可能调用LLM；retrieval-sweep/hybrid-ablation只检索但可能加载模型并入库。validate/build --check和指定dry-run不等于真实检索。正式执行先确认数据目录及费用。

## 4. 指标与审核

文档Hit/Recall/MRR、完整gold召回、evidence覆盖/精确包含、引用、拒答和延迟应分开。逐题失败比汇总分数更能揭示重复报道、候选截断和配额效应。不可回答题“进入LLM比例”在仅检索报告中是流程代理指标，不表示实际调用模型。

非严格校验只保证数据契约；strict要求真实人工签核。AI预审和自动全库检索不能代签；frozen_test不得参与调参。修订题库应保留父版、ID映射、修订规则和未改题证据。

## 5. 取舍与已知限制

黄金文档严格按ID计分可能把等价报道判为漏检；答案关键点匹配会受格式与同义改写影响。旧数据分数不能直接代入新版；CPU/GPU比较还需说明FP32/FP16差异。执行开发[DEV-011 评测CLI与数据集](../开发/DEV-011-评测CLI与数据集.md)，数据与运行验证[TEST-006 数据集与评测验收](../测试/TEST-006-数据集与评测验收.md)、[TEST-002 检索质量与性能](../测试/TEST-002-检索质量与性能.md)。

## 6. V3-5实验设计增量（A—F及补充B2已实现，G待执行）

本节是[OPT-003 A—G](../优化/OPT-003-候选深度与拒答门控.md#plan)的实验合同。已实现并验收A隔离能力、B模式消融、C Dense候选深度/阈值扫描、D重排/最终上下文预算、补充B2 Hybrid BM25/RRF坐标扫描、E离线门控及F validation验证；F结论为不采用，G和S7业务接入未开始。

- 输入锁定：dataset/corpus/manifest/parser/rubric、模型/精度、源码、基线索引身份及分区ID清单。JSON对象不改写，人工review仍draft。
- 存储：使用`eval/crud_rag_1000/v3_1/tuning/<experiment_id>/`；索引副本、metadata、cache、各config结果及运行日志均在该目录。prepare要求源与副本逐字节一致；Chroma打开后只允许SQLite内部运行簿记改变，HNSW和metadata.db哈希、quick_check、1000文档/2914 embeddings契约必须不变。
- 执行：`tuning_runner.py`显式构造请求级检索配置，经`eval.adapters.retrieve_only(runtime_config=...)`调用现有retriever。只允许development；不循环调用会清理run并重新入库的旧CLI。
- 重放：A只启用绑定题库、索引、检索/计分代码、环境、split、题目及完整配置的精确逐题结果缓存，用于同配置断点续算。跨配置阶段缓存未证明等价，保持关闭；新增候选必须真实补算。Dense阈值仍作用于Dense之后、RRF之前。
- 参数：持久化全部effective_config及派生fusion_pool_k，未生效字段应报错；CLI仍不消费生产UI的revision，不能伪造settings_revision。
- 产物：protocol/configs、输入与索引hash、逐题原始结果/Trace、分区/风险/修题分层指标、改善/回归队列、性能轮次及GPU证据、决策JSON/Markdown；实验缓存命中与真实时延明确区分。
- 门控：实验层另存simulated_gate和信号/阈值/原因；不修改真实Trace来冒充S7落地。业务接入需要另行同步DES-003/DES-006和开发/测试合同。
- 分区：只在development搜索，validation对有限候选做选择；已查看的frozen_test留作后续V3-6历史回归，不作为新的未见盲测。
- ANN比较控制：若HNSW持久化终点未覆盖全部embedding，跨进程单次结果不能作为微小参数收益。候选与control须在同一长生命周期进程交替执行并记录进程/次序，或改用已证明完全持久化的确定性控制索引；精确余弦可作质量oracle，但不能替代ANN性能链路。

失败处理：hash/参数/缓存一致性失败、索引副本不兼容、GPU不可用或成本超预算时停止说明；不能自动回退CPU、重建生产库、放宽评分或扩题。
实现计划见[DEV-011](../开发/DEV-011-评测CLI与数据集.md#tuning)，验收见[TEST-006](../测试/TEST-006-数据集与评测验收.md#tuning-gates)。

<a id="tuning-a-result"></a>
### 6.1 A阶段实际结果

实验`v35-a-baseline-20260829`复制1000篇/2914向量的封存测试索引，72道development实际检索全部获得Trace，参数72/72生效；Embedding和Reranker均核验为cuda:0，LLM模块未导入、无出站连接。60/60道可回答题最终顺序及全部质量指标与历史基线一致；历史run与A有10题Dense集合变化，但只有2道不可回答题传播到最终Top5，BM25仍72/72一致。复制库结果仍是A功能/质量control，但不能未经生命周期控制就用于跨进程单次ANN微比较。

初版验收将不可回答题候选差异也判为失败；修订后新增独立验收文件并保留初始失败summary。实际运行还证明Chroma打开副本会增加`acquire_write`簿记，故运行期使用不可变文件哈希加逻辑数据库契约，而不是错误要求整个SQLite永久逐字节不变。

<a id="dense-variance"></a>
补充诊断读取到metadata seq=2914、HNSW vector seq=2000及914条未同步尾段；全新隔离索引同进程/重开对照复现候选变化。15个独立进程中Embedding哈希不变而6/10题ANN状态变化，同进程内稳定。根因类别已确认到Chroma HNSW持久化/queue重放生命周期；多线程内部具体调度仍是强证据推断。用户随后确认按受控噪声继续，B使用同进程首尾control，详见[TEST-006补充验收](../测试/TEST-006-数据集与评测验收.md#dense-variance)。

<a id="tuning-b-result"></a>
### 6.2 B阶段实际结果

B入口在同一GPU进程按固定顺序运行六个唯一配置，并额外重复Hybrid+Reranker control；每轮72题，另1次预热，共505次真实检索。每一行均校验请求级effective_config，跨配置不复用结果缓存。control首尾的Dense raw/eligible、BM25、RRF、Reranker及selected均72/72顺序一致，证明本轮配置比较没有跨进程ANN污染。

实验目录、配置、逐题Trace、汇总和结论全部位于A实验目录的`phase-b/v35-b-mode-ablation-20260829/`子目录。Embedding与Reranker实际设备均为cuda:0；LLM模块未导入、0出站连接；索引逻辑契约、封存37文件和生产39文件保持不变。六组只改变mode和reranker_enabled，K15、阈值0.67、RRF60、Top5、每文档3块保持固定。C及以后必须使用新的阶段子目录和单独授权，不能在B产物上追加写入。

<a id="tuning-c-result"></a>
### 6.3 C阶段实际结果

C入口在新的`phase-c/v35-c-dense-quality-20260829/`目录运行，固定Dense+Reranker、Reranker K15、最终Top5和每文档3块。先比较`candidate_k={10,15,30,50}`，再按确定性规则选择K15并比较`distance={0.55,0.60,0.65,0.67,0.70,0.75}`；`fusion_pool_k`在Dense单路中明确记为不适用。每个候选均真实检索，不跨配置复用结果缓存。

同一GPU进程按Hybrid control前置、Dense control前置、参数候选、Dense control后置、Hybrid control后置共12轮执行72道development题，另加1次预热，共865次检索。运行器核对真实Trace的`dense/reranker/selected`阶段、原始候选数、阈值资格、重排输入集合/分数、最终结果和计时字段；两组control逐阶段72/72完全一致。Embedding与Reranker实际设备均为cuda:0，LLM模块未导入、0出站连接；索引逻辑契约、封存37文件和生产39文件保持不变。

同进程K15/0.67基线为Hit 98.33%、Recall 96.67%、MRR 0.9306、all-gold 57/60、多文档完整37/40、Evidence 96.51%。K10回归2题；K30/50最终质量及Top5集合与K15相同。阈值0.55/0.60分别回归2/1题；0.65/0.70/0.75虽无硬质量退步，也没有超越0.67。故质量优先选择仍为K15/0.67，不修改生产默认值。B与C跨进程同配置相差1道完整gold是已确认的ANN生命周期波动，不算作C收益。D必须使用新阶段目录和单独授权。

<a id="tuning-d-result"></a>
### 6.4 D阶段实际结果

D入口在新的`phase-d/v35-d-rerank-context-quality-20260830/`目录运行，固定Dense路线和distance 0.67。由于Reranker输入受前级实际候选限制，不能只改名义Reranker K；真实矩阵同时保留Dense K20/30/50+Reranker K15锚点，并测试K10、20、30、50的真实输入预算。每题核对Dense raw/eligible、Reranker集合/分数、selected及本地配额重放。

最终TopK/配额不重复模型推理：从获选真实配置的Reranker序列回查隔离Chroma完整metadata，再按业务`document_id`配额逻辑重放Top3/5/8/10与每文档1—4块。基线真实selected逐题与重放一致；unit/offset保留，Evidence Coverage可与真实链路使用同一口径。

同进程Dense15/Reranker15基线all-gold为56/60；Dense20/Reranker20改善1题到57/60且无回归，是最小重排质量平台。质量优先Top10/每文档2块达到Hit 100%、Recall 98.89%、all-gold 59/60、多文档完整39/40、Evidence 98.89%，但平均存储token约从1495增至2888，不能称为同预算收益。成本平衡Top5/每文档2块保持57/60且略减上下文。两组control逐阶段72/72精确稳定；两模型cuda:0、无LLM/出站连接、生产和封存文件不变。E必须使用新阶段目录和单独授权。

<a id="tuning-b2-result"></a>
### 6.5 补充B2 Hybrid BM25/RRF实际结果

B2固定D选出的真实前级预算Dense20/Reranker20，并固定distance 0.67、Top5/每文档3块，以便与同期Dense作同预算上游路线比较；它不把D的Top10质量上下文和Top5成本上下文混入词法参数因果判断。坐标依次为BM25 TopK 10/15/20/30/50、k1 0.8/1.2/1.5/2.0、b 0.25/0.5/0.75/1.0及RRF 20/40/60/80，共14个唯一Hybrid配置，不是笛卡尔积或全局最优证明。

同一GPU进程运行17轮、1224次正式检索和1次预热，wall 462.591s。每个Hybrid配置的Dense raw/eligible都与同期Dense control逐题精确相同；BM25 K扩展保持10组前缀关系，单改RRF的3组上游Dense/BM25保持不变，RRF逐题由双路排名重算一致。Dense与Hybrid首尾control各阶段均72/72精确一致。

跨配置18388次共享query-chunk重排分数比较中，205对、59题出现FP16量化抖动，最大绝对差0.01171875；验收容差固定为0.02，同时对604组相同Reranker候选集强制最终Top5完全一致。仅3组在第7/8名发生两次打分均完全相同的顺序反转，Top5变化为0；任何超容差、Top5变化或非同分反转都会失败。该双层门禁替代已证明不适合FP16的1e-6临时容差，不把数值抖动放宽成业务结果漂移。

最佳Hybrid为BM25 K50、k1=1.5、b=0.75、RRF=60，与Dense20/Reranker20的Hit 98.33%、Recall 96.67%、MRR 0.9306、all-gold 57/60、多文档完整37/40及Evidence 96.51%完全相同，逐题改善/回归/混合损失均为0。故B2选择保留Dense，不触发D有限复查，不修改生产设置；12道不可回答仍全部非空，E仍需单独授权。

<a id="tuning-e-result"></a>
### 6.6 E离线多信号门控实际结果

E入口只读取D已验收的`05-dense-k20-rerank-k20.jsonl`及Top10/配额2、Top5/配额2两个重放文件。输入题库、D汇总/最终核验和重放文件在运行前后逐文件hash一致；隔离库quick_check、1000文档/2914向量、封存37文件和生产39文件保持不变。E不导入检索模型或LLM，真实检索和生成调用均为0。

16个预注册策略包括关闭门控、7个Reranker Top1单阈值和M1—M8多信号规则。多信号先按Top1的low/high区分低分拒答和高分直通，中间灰区只有在“Dense eligible最佳距离”和“Reranker Top1对应Dense距离”都超过弱证据阈值时拒答。Reranker分数保留原始logit，不转换为概率；Top2、margin、Top3均值及支持数量仅记录诊断，不在首轮规则中增加自由度。

资格是硬门槛而非加权评分：0/60可回答误拒、至少9/12不可回答拦截，并对Top1 ±0.02、两项distance ±0.005的8角扰动保持72题决策不变。最终M2取`low=-2.5/high=0.5/dense_best_weak=0.52/top1_dense_weak=0.55`，拦截11/12、误拒0/60、扰动翻转0；M8表面12/12但有1道可回答及1道不可回答发生扰动翻转，严格淘汰。所选门控绑定两套D上下文后均把不可回答非空从12/12降到1/12，且可回答检索指标、逐题回归/混合损失保持0。实验只写独立`phase-e`产物和`simulated_gate`等价逐题决策，不改真实Trace、业务schema或生产设置。

<a id="tuning-f-result"></a>
### 6.7 F validation一次性验证实际结果

F入口只接受E最终核验中固定的M2，不暴露validation阈值参数；锁定20道可回答、4道不可回答、Dense20/Reranker20、Top10/配额2和Top5/配额2，并同时运行原始Hybrid15/Reranker15、Top5/配额3门控关闭基线。Top10是真实业务selected，Top5从同一20条Reranker序列按业务文档配额精确重放；门控开启/关闭共享检索结果，避免把门控效果与检索变化混淆。

正式调度为候选前置24题、原始基线24题、候选后置24题，另1次不计分预热。候选的Dense raw/eligible、Reranker及selected首尾24/24逐项一致；两模型actual device均为cuda:0，峰值allocated/reserved约2396/2522MiB。第一次误用CPU版`.venv`时防降级保护在预热中止，0次正式查询并保留失败目录；有效结果来自全新的`.venv-gpu` run，未覆盖失败证据。

F硬门槛在运行前固定为0/20可回答误拒、至少3/4不可回答拦截、0扰动翻转、all-gold至少19/20，且候选硬质量不得低于原始基线或产生逐题回归。实测M2为1/20误拒、1/4拦截、0/24扰动翻转；Top10与Top5均为18/20 all-gold并各有2道相对原始基线的可回答回归。故两个候选均不合格，选择器输出`not_adopted`和空配置；validation上不重新调阈值。F只证明固定策略未泛化到该留出分区，不代表正式盲测或总体拒答率；G、S7和生产修改均停止。
