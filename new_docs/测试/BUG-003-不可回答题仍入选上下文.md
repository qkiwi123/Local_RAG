## 1. 问题与证据

[120题预基线](../测试/TEST-002-检索质量与性能.md#evidence)记录20道不可回答题全部仍有最终检索结果。来源：[CPU/GPU对照](../../eval/crud_rag_1000/v3/runs/cpu-gpu-baseline-comparison-20260823/cpu-gpu-comparison.md)。

本Bug跟踪检索门控缺口；该运行未调用LLM，因此不能写成“20道题均发生幻觉”或“模型已全部调用”。

2026-08-28 v3.1固定GPU基线再次观测20/20不可回答题非空，见[新版测试证据](./TEST-002-检索质量与性能.md#baseline-v31)。这是上一阶段实际运行结果，本轮仅更新文档，未修复该Bug。

<a id="phase-e-offline"></a>
2026-08-31完成[E离线验收](./TEST-006-数据集与评测验收.md#v35-e)：M2在development固定D Trace上误拒0/60、拦截11/12，并对预注册分数/距离扰动保持稳定；两个D上下文候选的不可回答非空代理值降至1/12。该结果没有进入业务retriever或LLM，不能视为Bug已修复。

<a id="phase-f-validation"></a>
同日完成[F validation验收](./TEST-006-数据集与评测验收.md#v35-f)：固定M2在20道可回答中误拒1道，只拦截4道不可回答中的1道；Top10/Top5两个上下文候选也各有2道相对原始Hybrid基线的可回答回归。因此F按预注册规则输出`not_adopted`，没有可进入G/S7的候选。该结果进一步证明E的development分离不能外推到validation，不能以放宽门槛或在该24题上重调阈值关闭Bug。

## 2. 原因与影响

Dense阈值只过滤Dense候选；BM25正分候选可通过RRF/精排进入最终上下文。当前没有经过校准的最终拒答门控，相关schema拒绝启用开关。影响无关证据输入及潜在错误回答风险。

## 4. 回归计划

在用户已接受的draft探索范围内，先使用development校准，validation对有限候选比较；测不可回答拦截、可回答误拒答和多文档证据保留。v3.1已有固定基线，但仍draft；原frozen_test已被查看，仅保留给后续V3-6历史回归，不冒充新盲测。

E的离线模拟与F的固定验证均已完成，但F否决当前M2/上下文候选。下一方案必须重新回到development提出有独立依据的新规则，并使用新的独立验证样本；不能继续消费当前validation调参。只有新方案再次通过验证且用户确认S7实现后，才落地检索/设置/Trace及API回归。development模拟通过不能关闭本Bug。

离线回归结果：E的145项及F的164项相关测试均通过，逐题策略、输入hash、CPU环境失败run、有效GPU run和最终核验已保存；但F效果门槛失败。业务回归不应在当前候选上启动；只有新策略验证、S7代码、真实Trace/API测试和后续验证完成后，才能修改本Bug状态。
