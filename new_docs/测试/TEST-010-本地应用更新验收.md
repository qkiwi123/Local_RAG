## 3. 真实旧版本升级

[probe_update.py](../../deploy/windows/probe_update.py)仅允许在新build/windows-update子目录中建立副本。基包为已记录的642c2809内部W4完整包，旧SQLite v5；保护的模型/runtime/许可用硬链接复用为输入，应用文件及合成data独立。只替换应用，禁止写保护资产。

真实过程：CPU启动旧版→创建标签→保存分块长度420→上传合成TXT→等待真实BM25就绪→以真实向量/重排检索生成仅检索回答并保存两条消息→从解压包执行独立更新入口→旧实例正常退出→备份/替换→SQLite升v6→CPU新实例启动→复核状态与再次真实检索→停止验收服务。

结果：通过。工作空间ID不变；标签、设置revision及420字符参数保留；两条消息正文相同，旧范围为null；原文和索引直接沿用，升级后仍有来源，未重新上传；更新状态completed，最终服务记录已移除。原始acceptance.json和commands.log保存在本机验收目录，不随更新包发布。此结果不代表真实生成API、GPU升级矩阵、无驱动干净机或生产规模性能。

## 4. 浏览器与未验收边界

真实升级副本的设置页存在“关于与更新”、本地ZIP选择与完成刷新入口，页面保持原设置。真实1280/390视口的更新分区、选择按钮和成功刷新提示可见；页面宽度不超过视口，控制台错误为空。最终ZIP不含模型/runtime或个人资料，约2.4 MB；最终交付版本为`local-b98d3a18e05d`，ZIP为2404431字节；确切SHA-256及支持基包身份见包旁JSON。最终包独立执行旧版升级通过，验收服务已停止。网页API提交/确认与事务由自动化验证；Windows PowerShell语法解析无错误、中文标题按UTF-8 BOM正确读取；首次接入的Windows原生文件/目录选择框未完成人工鼠标点选，不把引擎CLI通过等同原生双击完整人工验收。

断电/磁盘损坏、所有文件落盘窗口及任意跨版本迁移未穷尽；备份损坏时明确阻止自动恢复并保留现场，不宣称永不丢失。SHA-256为完整性检查，首版没有在线更新或发行者签名认证。原W5/许可发行门禁继续保留，见[OPS-005](../运维/OPS-005-Windows单人本地发布与初始化方案.md#offline-update)。
